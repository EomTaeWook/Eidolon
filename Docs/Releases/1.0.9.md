# Eidolon 1.0.9

## 한국어

- 설정의 앱 업데이트 화면에 현재 버전과 최신 정식 버전을 함께 표시합니다. 최신 버전은 기존 GitHub 조회 결과를 사용하며, 조회 결과가 없으면 대시로 표시합니다. 조회 중·실패·정식 릴리스 없음은 기존 상태 문구로 확인할 수 있습니다.
- 앱 도움말과 한·영 README에 `ModelingNotes` 위치와 사용 방법을 추가했습니다. 문서는 다음 모델링 작업부터 참고하며 사용자가 직접 관리합니다.
- 한·영 README의 라이선스·릴리스 안내 링크를 수정하고, 소스 실행의 서브모듈 초기화 및 macOS 실행·데이터 저장·업데이트 안내를 보완했습니다.

다운로드: [Windows x64](https://github.com/EomTaeWook/Eidolon/releases/download/v1.0.9/Eidolon-v1.0.9-win-x64.exe) · [macOS 14+ Apple Silicon](https://github.com/EomTaeWook/Eidolon/releases/download/v1.0.9/Eidolon-v1.0.9-osx-arm64.app.zip) · [macOS 14+ Intel](https://github.com/EomTaeWook/Eidolon/releases/download/v1.0.9/Eidolon-v1.0.9-osx-x64.app.zip)

Windows는 EXE를 실행합니다. macOS는 ZIP을 풀고 `Eidolon.app`을 Applications 폴더로 옮겨 실행합니다. 별도 .NET 설치는 필요 없습니다. macOS 패키지는 공증되지 않아 처음 실행할 때 시스템에서 허용해야 할 수 있습니다.

배포 워크플로는 동일한 소스 커밋에서 세 플랫폼 패키지를 만들고 SHA-256을 기록합니다. 앱 실행·화면 표시와 앱 내 업데이트 설치는 별도로 검증하지 않았습니다.

## English

- Settings > App updates now shows both the current version and the latest stable version. The latest version comes from the existing GitHub release check, or displays a dash when unavailable. Existing status messages distinguish checking, errors, and no published stable release.
- App Help and both READMEs explain where to put `ModelingNotes` and how to use them. Notes are read for the next modeling job and are maintained by the user.
- Both READMEs have corrected license and release links, submodule initialization instructions, and expanded macOS launch, data location, and update guidance.

Downloads: [Windows x64](https://github.com/EomTaeWook/Eidolon/releases/download/v1.0.9/Eidolon-v1.0.9-win-x64.exe) · [macOS 14+ Apple Silicon](https://github.com/EomTaeWook/Eidolon/releases/download/v1.0.9/Eidolon-v1.0.9-osx-arm64.app.zip) · [macOS 14+ Intel](https://github.com/EomTaeWook/Eidolon/releases/download/v1.0.9/Eidolon-v1.0.9-osx-x64.app.zip)

On Windows, run the EXE. On macOS, extract the ZIP, move `Eidolon.app` to Applications, and open it. No separate .NET installation is needed. The macOS packages are not notarized, so first launch may require system approval.

The release workflow builds all three platform packages from the same source commit and records their SHA-256 hashes. App launch, UI display, and in-app update installation were not separately verified.
