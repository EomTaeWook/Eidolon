# Eidolon 1.0.2

## 한국어

배포일: 2026-11-03 (한국 시간)

### 다운로드

- Windows x64: [Eidolon-v1.0.2-win-x64.exe](https://github.com/EomTaeWook/Eidolon/releases/download/v1.0.2/Eidolon-v1.0.2-win-x64.exe)
- .NET 런타임과 UI·문자열·고지를 포함한 단일 EXE입니다. 다운로드한 파일을 더블클릭해 실행합니다. 생성·학습 엔진과 모델 가중치는 별도로 준비합니다.

### 이번 변경

- `eidolon_cancel_work`로 실행 중인 생성·참고 생성·편집·프롬프트 변환·학습·다면도·큐 유지 관리 작업의 취소를 요청합니다. 상태 조회에서 받은 현재 작업 제목을 확인하고 기존 취소 토큰으로 전달합니다.
- `eidolon_clear_pending`으로 공용 큐의 대기 요청 전체를 비웁니다. UI와 다른 MCP 클라이언트의 대기 요청도 포함하며 현재 작업과 완료 파일은 유지합니다. 시작 전 유지 관리 요청을 비웠을 때 입력 제한도 해제합니다.
- 학습 전용 `eidolon_cancel_training`을 제공하고 기존 취소 중 표시·프로세스 정리·엔진 복구와 완성 LoRA 등록 단계 보호를 유지합니다.
- 상태 조회에 `can_cancel_work`·`can_cancel_training`·`pending_requests`를 추가합니다. 취소 신호 접수와 실제 업무 종료를 구분합니다.
- 진행 중인 조회·준비·내보내기 HTTP 호출에 대해 요청 ID 기반 `notifications/cancelled`를 2025 계열과 `2026-07-28` 경로에 연결합니다. 이미 큐에 접수된 업무는 공통 업무 취소 도구로 중단합니다.
- 요청 제목을 확인하는 취소 경로와 사용법을 문서화했습니다. 제목은 고유 작업 ID가 아니며 완료된 파일 쓰기·삭제를 취소로 되돌리지 않습니다.

### 확인한 범위와 제한

- 기존 WindowsX64 프로필로 Release·Windows x64 자체 포함 단일 EXE를 생성했습니다.
- 테스트·앱 실행·실제 생성 또는 학습 취소·HTTP 취소·대기열 비우기·앱 내 업데이트 설치는 이번 배포 작업에서 실행하지 않았습니다.
- 취소는 협력적 중단 요청입니다. 완료한 파일과 되돌릴 수 없는 삭제는 보존된 결과 그대로 남으며 내보내기 중 작성한 일부 파일의 롤백을 보장하지 않습니다. 현재 작업만 취소하면 대기 중인 다음 작업이 실행될 수 있습니다.

## English

Release date: 2026-11-03 (Korea Standard Time)

### Download

- Windows x64: [Eidolon-v1.0.2-win-x64.exe](https://github.com/EomTaeWook/Eidolon/releases/download/v1.0.2/Eidolon-v1.0.2-win-x64.exe)
- A single executable including the .NET runtime, UI libraries, localized resources and notices. Double-click the downloaded file to run it. Generation/training engines and model weights are prepared separately.

### Changes in this release

- Added `eidolon_cancel_work` for active generation, reference generation, editing, prompt conversion, training, multi-view work and queued maintenance. It checks the current title from status and signals the existing cancellation token.
- Added `eidolon_clear_pending` to discard all waiting shared-queue requests, including UI and other MCP clients' requests, while preserving active work and completed files. Discarding maintenance before it starts also releases its input restrictions.
- Added the training-specific `eidolon_cancel_training` while preserving cancellation state, process cleanup, engine recovery and protection during final LoRA registration.
- Added `can_cancel_work`, `can_cancel_training` and `pending_requests` to status. Cancellation acceptance is distinct from actual work completion.
- Connected request-ID-based `notifications/cancelled` for in-flight queries, preparation and exports in both 2025 protocols and the `2026-07-28` path. Accepted background work uses the shared-work cancellation tools.
- Documented cancellation targets and lifecycle boundaries. A title is not a unique job ID, and cancellation does not undo completed writes or deletions.

### Validation and limitations

- Produced a Release, self-contained Windows x64 single-file executable using the existing WindowsX64 profile.
- No tests, app launch, actual generation/training cancellation, HTTP cancellation, pending-queue clearing or in-app update installation were performed during this release task.
- Cancellation is cooperative. Completed writes and irreversible deletions are not rolled back, and partial export files may remain. Cancelling only active work can allow the next waiting request to start.
