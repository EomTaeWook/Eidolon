# 3D 모델링

3D 모델링 탭은 Blender에서 모델을 만들거나 기존 장면을 수정하는 작업을 돕는다. 캐릭터, 크리처, 배경, 소품을 같은 방식으로 다룬다. 기존 에셋 제작 탭의 다면도는 이 작업에 참고 자료로 사용할 수 있는 이미지다.

## 준비와 입력

이미지 생성 화면과 같은 방향으로 배치한다. 왼쪽은 결과와 그 아래의 모델링 요청·실행 영역, 오른쪽은 입력 방식과 Blender 옵션이다. 결과가 비어 있어도 입력과 실행 위치를 옮기지 않는다.

- 엔진 탭에서 Blender를 설치한다. 엔진 설치 폴더가 `D:\AI`라면 실행 파일은 `D:\AI\Blender\Blender-4.5.16` 아래에 설치한다. 같은 `Blender` 폴더에 설치 다운로드와 로그를 보관하며, ComfyUI·학습이 관리하는 `EidolonRuntime`은 변경하지 않는다.
- 저장된 엔진 설치 경로를 사용한다. 처음 경로를 정하는 경우 엔진의 기존 경로 입력을 사용하고 Blender 설치가 성공한 뒤 그 경로만 저장한다. 모델링 실행은 같은 저장 경로의 Blender를 사용한다. 기존 앱 데이터에 설치된 Blender 파일과 모델링 결과는 이동하거나 삭제하지 않는다.
- **모델링 노하우**: 설정의 **엔진 설치·연결**에서 선택한 공통 경로 바로 아래 `ModelingNotes`에 UTF-8 `.md`를 둔다. 예를 들어 `D:\AI`를 선택했다면 `D:\AI\ModelingNotes`가 `D:\AI\Blender`와 `D:\AI\EidolonRuntime` 옆에 생긴다. Blender 설치 또는 첫 모델링 작업에서 폴더를 만들며, 같은 설치 경로에서는 Blender 버전을 바꿔도 그대로 쓴다.
- 화면과 MCP 작업 모두 시작할 때 이 폴더 바로 아래의 Markdown을 파일명 순으로 읽어, 원본 파일 크기 합계 48 KiB 안에 들어가는 문서를 모델링 에이전트에 참고 자료로 전달한다. 읽을 수 없는 문서는 건너뛴다. 문서 변경은 다음 작업부터 반영되며, 포함된 내용은 해당 작업의 `PlanRequest.txt`에도 남는다. 문서는 사용자가 관리한다.
- 설치 파일은 Blender 4.5.16 LTS의 Windows x64 ZIP 또는 macOS Apple Silicon·Intel DMG를 사용하고, [Blender 공식 SHA-256 목록](https://download.blender.org/release/Blender4.5/blender-4.5.16.sha256)의 값을 확인한다.
- AI 요청은 기존 생성 환경에 설정된 Codex 실행 경로·모델과 기존 로그인을 사용한다. 사용 모델은 참고 이미지와 렌더를 볼 수 있어야 한다.
- 입력은 **이미지 1장**과 **다면도** 탭에서 각각 선택한다. 다면도 탭에는 정면·좌측·우측·후면 파일을 따로 넣고 교체하거나 제거할 수 있다. 빈 방향은 생략하고, 실행에는 현재 탭의 입력만 사용한다.
- 기존 `.blend` 없이 새 모델을 만들 때는 현재 탭에 실제 이미지 입력이 있으면 설명을 비워도 요청할 수 있다. 직접 선택하거나 이전 결과에서 이어 수정하는 `.blend` 작업은 바꿀 내용을 반드시 입력한다.
- **기존 다면도 불러오기**를 열면 별도 선택창에서 실제 대표 이미지와 파일명·완료 방향 수를 보고 묶음을 고른다. 완료된 정면을 대표 이미지로 사용하고, 정면이 없으면 다른 완료 방향을 사용한다. 카드를 누르면 해당 묶음만 빈 방향에 채운다. 과거 묶음에 저장된 윗면은 입력으로 가져오지 않는다. 좌우가 정해지지 않은 과거 측면은 따로 표시하고 `side` 라벨 그대로 전달한다. 탭 전환과 묶음 새로고침으로 이미 선택한 파일을 지우지 않는다.
- 선택창의 썸네일은 열었을 때 현재 페이지의 최대 6개만 작은 크기로 순서대로 읽는다. 이전·다음으로 과거 묶음에도 접근하며 선택창이 본문 높이와 옵션 폭을 바꾸지 않는다. 페이지 전환·닫기·종료에서는 읽기를 취소하고 썸네일을 해제하며 늦은 읽기 결과를 적용하지 않는다.
- 기존 장면을 수정할 때는 `.blend` 파일과 바꿀 내용을 선택한다. 참고 이미지를 추가할 수 있고, 이전 모델링 결과를 다음 작업의 장면으로 사용해 수정할 수 있다.
- 최대 삼각형 수는 `0`(자동) 또는 `1`~`1,000,000`으로 지정한다. 요청에 고정한 값을 내보낼 모델에 적용한다. 자동에서는 삼각형 수를 맞추기 위해 형상을 줄이지 않는다.

## 작업과 결과

**Blender 부품 불러오기**에서 부품 원본 `.blend` 하나를 선택하고, 만들거나 바꿀 내용에 가져올 오브젝트 또는 컬렉션을 적는다. 기존 장면 수정용 파일과 함께 선택할 수 있다. 참고 이미지 없이 부품만 불러오는 작업도 설명이 있으면 접수할 수 있다. 선택은 해당 요청에만 전달되며, 모델링 에이전트에는 파일 경로 대신 선택한 파일에 있는 오브젝트와 컬렉션 이름을 제공한다.

키트의 `append_part`는 지정된 부품을 편집 가능한 로컬 복사본으로 추가한다. 여러 오브젝트가 필요한 부품은 원본 파일에서 한 컬렉션으로 묶어 둔다. 불러온 컬렉션은 내부 배치를 유지하고 새 그룹 기준점으로 움직인다. 외부 라이브러리를 연결한 채 유지하는 Link는 이 흐름에서 지원하지 않는다. 재사용할 부품은 로컬 메시·커브로 구성하고 외부 텍스처는 원본에 패킹해 둔다. 원본 파일은 결과 저장으로 덮어쓸 수 없다. 부품 원본은 모델링 화면에서 선택하며 MCP 입력에는 추가하지 않았다.

예를 들어 노하우에 ‘여러 조각으로 된 장식은 컬렉션째 불러오고, 붙는 뿌리를 받치는 표면에 맞춘다’라고 적을 수 있다. 노하우는 적용 방법을 제안하며, 실제 부품은 기존과 같이 사용자가 선택한 원본 `.blend`에 있고 재사용을 요청했을 때만 가져온다. 문서 안의 파일 경로나 명령을 실행하지 않는다.

Eidolon은 기본적으로 Blender를 창 없이 실행한다. Blender 창 표시 옵션을 켜면 해당 요청의 Blender 창만 열린다. 두 모드는 같은 파일 명령, 렌더, 삼각형 제한, 저장과 취소 방식을 사용한다. 창 없이 실행할 때도 EEVEE 렌더에 필요한 GPU 환경을 사용한다. AI는 참고 이미지와 현재 장면의 객체 정보, 기존 장면을 수정하는 경우 그 장면의 렌더를 보고 모델링 작업을 한 번 작성한다. 내장 키트는 허용된 모델링 함수 호출과 리터럴 값을 읽어 적용한다. 기본 도형·사용자 정의 메시·곡선·재질·배치 등으로 모델을 만들거나 지정한 부품을 수정한다. AI가 생성한 일반 Python 파일을 그대로 실행하지 않는다.

모델링 계획은 여러 방향의 원본에서 폭·높이·깊이와 부품 배치를 공통 치수로 맞춘다. 배경이 투명하거나 테두리 배경이 균일한 방향에는 키트가 높이별 윤곽의 좌우 끝을 대상 높이에 대한 비율로 추정해 사진과 함께 전달한다. 색 영역이 뚜렷한 이미지는 각 높이에서 넓게 이어지는 색 구간도 전달해 윤곽 안에서 겹치는 부분의 경계를 판단하도록 돕는다. 이 값은 부품을 구분하지 않으며, 배경과 비슷한 색의 부위나 장식 때문에 실제 사진과 다르면 사진을 기준으로 삼는다. 외곽을 얻을 수 없는 방향은 원본만 전달한다. 윤곽과 접합을 먼저 맞추고 표면 마감은 마지막에 한다.

얇은 디테일을 지정한 방향에서 보이는 첫 표면에 붙일 때는 `project_surface`를 사용한다. 바깥쪽에 만든 메시의 정점마다 광선을 쏘고, 모두 맞았을 때만 결과를 적용한다. 작은 장식에서 크기와 위치를 조금 바꿔도 된다면 투영이 빗나갈 때 허용할 최소 크기와 중심 이동 거리를 지정할 수 있다. `surface_error`를 양의 표면 띄움 거리보다 작게 지정하면 면 내부도 확인하고, 오차가 큰 경우 메시를 나눠 다시 투영한다. 나뉜 면은 원래 재질을 이어받으므로 면 번호로 색을 지정하는 작업은 투영보다 먼저 한다. 이 옵션은 UV를 입히기 전 사용한다. `fit_surface`는 가장 가까운 표면을 따라가게 하는 모디파이어를 붙이고, `attach_to_surface`는 기준점 하나를 맞춰 부품 전체를 옮긴다.

휘어진 꼬리나 손잡이처럼 타원 단면을 잇는 부품은 `loft_path`로 만든다. 단면 중심과 폭·높이 반경을 넣으면 단면 축이 경로를 따라 회전하고 양 끝이 닫힌 메시가 생성된다. 끝이 이웃 메시의 윤곽 밖으로 일정 길이 보여야 한다면 `beyond`로 대상과 방향, 노출 길이를 지정한다. 단면 모양이나 비틀림을 직접 지정해야 하면 기존 `loft`에 링을 전달한다.

곡면을 따라가는 연속 레이어는 `surface_sheet`로 만들 수 있다. 외곽과 중간 줄을 지정하면 키트가 줄 사이를 채우고, 지정한 방향에서 처음 보이는 메시 표면에 깊이를 맞춘다. 줄마다 바깥으로 띄우거나 안쪽으로 묻는 거리를 정한다. `minimum_width_scale`을 지정하면 가장자리가 표면을 벗어난 줄만 중심을 유지한 채 좁혀 본다. 그래도 닿지 않으면 메시를 만들지 않는다.

`radial_loft`는 높이별 단면을 잇고 맨 아래 가장자리의 높이와 반경 배율을 각도별로 지정한다. 단면은 기본 타원이며, `section_power`를 2보다 크게 주면 같은 폭과 깊이를 유지하면서 모서리가 둥근 사각형에 가까워진다. 아래를 열어 두면 입구와 이어진 밑단을 한 메시로 만들 수 있다. `cover_target`과 `clearance`를 지정하면 안쪽 메시가 겉면을 뚫는 부분의 반경을 늘린다. 단면 사이는 기본으로 부드럽게 잇고 각진 윤곽이 필요하면 `profile_steps`를 1로 지정한다. 두께가 필요하면 별도로 지정한다.

곡면에 원형이나 타원형 표시를 붙일 때는 `surface_oval`로 곡면에 맞는 메시를 만들고 접촉 거리도 확인할 수 있다. 이미지에서 읽은 색을 재질에 넣을 때는 `material`에 `"srgb"`를 지정하면 Blender가 사용하는 선형 값으로 변환한다.

`outline_plate`는 외곽선과 그 평면의 두 방향을 받아 두께가 있는 부품을 만든다. 정면과 옆면 모두에서 넓게 보이는 얇은 부품은 평면의 방향을 맞춰 두께를 늘리지 않고도 두 방향의 윤곽을 맞출 수 있다. 필요한 경우 `z_span`으로 두께를 넣기 전 외곽선의 세계 좌표 높이를 맞춘다. `exposure`에 가리는 메시, 관찰 방향, 드러낼 외곽점과 여유 거리를 지정하면 실제 표면을 기준으로 부품을 옮긴다. 묻힌 접합점이 빠지지 않는 범위에서만 움직인다. 다른 방향의 윤곽이 정해져 있으면 이동 거리 상한도 지정할 수 있다.

표면에 색 변화나 결이 필요하면 메시를 확정한 뒤 `project_uv`로 평면 또는 원통 UV를 만들고, `apply_surface_texture`로 지정한 두 색과 무늬를 재질에 연결한다. 한 메시에서만 쓰는 재질은 `finish_surface`로 기존 색을 기준으로 한 약한 색 변화와 UV를 한 번에 적용할 수 있다. UV 투영은 형상을 바꾸지 않는다. 키트가 색상 이미지를 생성해 Blender 파일에 포함하고 GLB 내보내기에 전달한다. 참고 사진 자체를 투영하거나 외부 파일을 읽는 명령은 아니다. 앱의 현재 3D 미리보기는 GLB의 기본 재질색을 사용하며 이미지 텍스처는 Blender 렌더와 저장한 파일에서 확인한다.

매 작업에 전달하는 모델링 지침은 큰 형태와 자세, 접합, 얇은 디테일, 재질 순으로 계획을 점검하게 한다. 얇은 패치에 `check_surface_gap`을 지정하면 키트가 정점, 모서리와 면 내부의 샘플에서 투영 방향의 첫 표면을 기준으로 돌출과 매입을 확인한다. 허용 거리를 벗어나거나 표면을 못 찾으면 메시를 바꾸지 않고 작업 오류로 보고한다. 모델링 명령 실행 오류에는 실패한 명령의 순번과 이름이 포함된다. 샘플 사이의 모든 점이나 원본과의 시각적 일치까지 검사하지는 않는다.

의상에 장식이나 테두리를 붙이기 전에 옷깃 사이 간격, 소매의 앞뒤 끝선, 손과 피부가 보이는 위치를 각 방향에서 맞춘다. 손목 아래로 늘어지는 천은 앞뒤의 낮은 끝과 그 사이 손목 개구부가 분리된 열린 곡면으로 만들고 얇게 두께를 준다. 테두리가 평평하면 같은 메시의 가장자리 면에 배색한다. 어깨를 감싸는 장식은 옆면에서 보이는 폭과 끝선을 유지하면서 천 표면에 붙인다.

붙지 않아도 전체 모델을 사용할 수 있는 작은 단색 장식에는 `optional_surface_patch` 또는 `optional_surface_oval`을 사용한다. 마름모 무늬는 `surface_diamond`에 표식이 가장 넓게 보이는 방향을 주면 실제 대상의 바깥에서 광선을 쏜다. 표면을 못 찾거나 접촉 검사를 통과하지 못하면 새 장식만 제거하고 Blender 로그에 남긴다. 눈이나 주요 부품에는 이 옵션을 사용하지 않는다. 굽은 면에 그려진 선은 `surface_stroke`로 선의 중앙과 가장자리를 함께 투영한다.

Blender가 작업을 적용해 렌더와 파일을 저장하고 검증을 마치면 그 결과를 바로 반환한다. 내부 Blender 결과 렌더의 `top`은 입력 방향 제한과 별개로 유지한다. 결과 렌더를 AI에 다시 보내는 자동 보정이나 최종 비교는 없다. 결과 화면에서 GLB를 3D로 확인하고 저장된 결과 위치를 열 수 있으며, 바꿀 부분이 있으면 **이 모델 이어서 수정**으로 새 작업을 요청한다. 새 요청의 `.blend`, `.glb`와 렌더는 기존 `Modeling/<요청 ID>/Draft`에 저장하고 작업 로그는 요청 폴더에 남긴다. 선택한 원본 모델과 과거 결과는 그대로 보존한다.

결과에는 내보낸 GLB의 실제 삼각형 수를 기록한다. 상한을 초과한 경우에만 출력용 작업 장면의 지오메트리를 필요한 만큼 줄이며, 상한 이하이면 수를 맞추기 위해 형상을 바꾸지 않는다. 렌더와 `.blend`, `.glb`는 같은 결과 형상을 담는다. 최종 GLB가 상한을 충족하지 못하면 실패로 처리한다.

현재 연결은 앱이 Blender와 Codex를 실행하는 방식이다. Blender MCP 애드온이나 MCP 연결은 필요하지 않다. 모델링 요청은 앱의 공용 작업 큐에 접수하며 취소·종료는 해당 요청이 시작한 프로세스에 적용한다.

모델링을 개선할 때 [비교 스크립트](../Scripts/Compare-Modeling.py)에 마지막으로 채택한 기준본과 새 후보본의 Blender 파일을 전달한다. 화면에서 두 모델의 높이를 맞추고 같은 직교 카메라와 조명을 사용한다. 각 방향의 PNG에는 왼쪽부터 참고 이미지(있으면), 기준본, 후보본이 나온다. 참고 폴더에는 `Front`, `Left`, `Right`, `Back` 이름의 PNG·JPEG·WebP를 둘 수 있다. 절대 크기는 비교하지 않으며 원본 파일도 바꾸지 않는다.

각 라운드에서 가장 큰 차이 한 가지를 골라 별도 후보를 만든다. 새 출력 폴더에서 스크립트를 다시 실행한 뒤, 다른 방향에서 악화된 곳이 없을 때만 후보를 다음 기준으로 삼는다. 형상과 접합을 먼저 볼 때는 `--clay`를 붙이고, 한 부위만 검토할 때는 `--views front left`처럼 방향을 좁힌다. 후보를 확정할 때는 네 방향을 모두 확인한다. 스크립트는 비교 이미지를 만들며, 차이 판단과 재생성은 작업자가 한다.

```powershell
blender --background --disable-autoexec --python-exit-code 1 --python Scripts/Compare-Modeling.py -- --baseline baseline.blend --candidate candidate.blend --references references --output artifacts/model-comparison
```

## 모델링 MCP

App의 `eidolon_model_3d`는 화면 입력을 바꾸지 않고 같은 `ModelingInput`, 공용 FIFO와 `ModelAsync` 실행 경로에 요청을 추가한다. 이미지 생성 방식과 별개로 저장된 네이티브 GPT(Codex CLI) 실행 파일·모델과 설치된 Blender를 사용한다. 요청 시 설정·참조 경로·수정 원본·설명·삼각형 상한을 사본으로 고정하고, 설치·로그인·초기화·종료·유지 관리 조건을 확인한 뒤에만 접수한다. Claude나 WSL 실행으로 전환하지 않으며 Blender 창 표시는 기본 꺼짐이다.

`reference_path` 한 장 또는 `views`의 `front`·`left`·`right`·`back`을 받으며 `top`은 거절한다. 둘을 동시에 받지 않는다. 기존 `.blend`를 수정하는 `source_blend_path`에는 설명이 필수이며, 새 모델은 이미지가 있으면 설명을 비울 수 있다. 입력은 절대 로컬 경로의 기존 PNG·JPEG·WebP와 `.blend`다. Windows의 UNC·디바이스 접두사는 파일 존재 확인·읽기·디코딩 전에 거절한다. 이미지는 기존 App 로더의 32MB·4천만 픽셀 제한과 디코딩 검사를 거친다. 파일 내용은 실행을 시작할 때 기존 엔진이 요청 폴더에 복사하므로 시작 전 원본을 옮기거나 변경하지 않는다. 투명도·방향 라벨은 그대로 전달한다.

접수 응답의 `request_id`는 기존 `Modeling/<GUID>` 경로의 GUID이며 완료를 뜻하지 않는다. MCP 요청의 공용 대기 제목은 `3D [<GUID>]`다. `eidolon_get_modeling_result`는 GUID만 받아 관리 경로의 `Control/Draft.json`과 비어 있지 않은 `Draft/Model.blend`·`Draft/Model.glb`를 확인한 뒤 완료 경로와 키트가 기록한 실제 내보내기 삼각형 수를 반환한다. 링크를 경유하는 결과 경로와 임의 조회 경로는 받지 않는다. 기존 자동 보정 시기의 `Refined`가 있는 작업은 최종 선택을 추측하지 않고 `unknown`으로 반환한다.

대기·실행은 기존 큐와 현재 모델링 입력에서, 최근 취소·실패는 화면의 기존 실행 상태에서 확인한다. 과거 실패는 기존 `Failure.txt` 존재만 확인하고 내용을 읽어 노출하지 않는다. 별도 결과 저장소나 취소 이력 파일은 만들지 않는다. 시작 전 대기 비우기, 더 오래된 취소, 앱 재시작 등으로 증거가 남지 않은 요청은 `unknown` 또는 `not_found`이며 취소·실패·완료로 단정하지 않는다. 공용 상태·정확한 현재 요청 제목·취소·대기 비우기는 [MCP 문서](Mcp.md#3d-모델링-도구)의 기존 도구를 사용한다.

실행 파일·작업 폴더·출력 경로·스크립트·임의 Python을 도구 인자로 지정할 수 없다. 결과 파일 읽기 외 전송 확장은 추가하지 않았으며, 실제 모델링·MCP 호출·앱 실행·빌드·테스트 검증은 수행하지 않았다.

## 소유 경계

`Eidolon.Modeling`은 기존 Eidolon 솔루션 안의 별도 프로젝트이며 `Eidolon.Core`, Avalonia, Eidolon 앱을 참조하지 않는다. Blender 설치, 모델링 실행, 키트와 입력·결과 계약은 모델링 프로젝트가 소유한다. Eidolon 앱이 프로젝트 참조를 통해 기능을 조립하고 기존 다운로드·프로세스 실행과 큐를 연결한다. 엔진·모델링 화면의 번역과 상태 표시는 App이 소유한다.
