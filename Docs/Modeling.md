# 3D 모델링

3D 모델링 탭은 Blender에서 모델을 만들거나 기존 장면을 수정하는 작업을 돕는다. 캐릭터, 크리처, 배경, 소품을 같은 방식으로 다룬다. 기존 에셋 제작 탭의 다면도는 이 작업에 참고 자료로 사용할 수 있는 이미지다.

## 준비와 입력

이미지 생성 화면과 같은 방향으로 배치한다. 왼쪽은 결과와 그 아래의 모델링 요청·실행 영역, 오른쪽은 입력 방식과 Blender 옵션이다. 결과가 비어 있어도 입력과 실행 위치를 옮기지 않는다.

- 엔진 탭에서 Blender를 설치한다. 엔진 설치 폴더가 `D:\AI`라면 실행 파일은 `D:\AI\Blender\Blender-4.5.16` 아래에 설치한다. 같은 `Blender` 폴더에 설치 다운로드와 로그를 보관하며, ComfyUI·학습이 관리하는 `EidolonRuntime`은 변경하지 않는다.
- 저장된 엔진 설치 경로를 사용한다. 처음 경로를 정하는 경우 엔진의 기존 경로 입력을 사용하고 Blender 설치가 성공한 뒤 그 경로만 저장한다. 모델링 실행은 같은 저장 경로의 Blender를 사용한다. 기존 앱 데이터에 설치된 Blender 파일과 모델링 결과는 이동하거나 삭제하지 않는다.
- 설치 파일은 Blender 4.5.16 LTS의 Windows x64 ZIP 또는 macOS Apple Silicon·Intel DMG를 사용하고, [Blender 공식 SHA-256 목록](https://download.blender.org/release/Blender4.5/blender-4.5.16.sha256)의 값을 확인한다.
- AI 요청은 기존 생성 환경에 설정된 Codex 실행 경로·모델과 기존 로그인을 사용한다. 사용 모델은 참고 이미지와 렌더를 볼 수 있어야 한다.
- 입력은 **이미지 1장**과 **다면도** 탭에서 각각 선택한다. 다면도 탭에는 정면·좌측·우측·후면 파일을 따로 넣고 교체하거나 제거할 수 있다. 빈 방향은 생략하고, 실행에는 현재 탭의 입력만 사용한다.
- 기존 `.blend` 없이 새 모델을 만들 때는 현재 탭에 실제 이미지 입력이 있으면 설명을 비워도 요청할 수 있다. 직접 선택하거나 이전 결과에서 이어 수정하는 `.blend` 작업은 바꿀 내용을 반드시 입력한다.
- **기존 다면도 불러오기**를 열면 별도 선택창에서 실제 대표 이미지와 파일명·완료 방향 수를 보고 묶음을 고른다. 완료된 정면을 대표 이미지로 사용하고, 정면이 없으면 다른 완료 방향을 사용한다. 카드를 누르면 해당 묶음만 빈 방향에 채운다. 저장된 윗면과 좌우가 정해지지 않은 과거 측면은 따로 표시하고 해당 라벨 그대로 전달한다. 탭 전환과 묶음 새로고침으로 이미 선택한 파일을 지우지 않는다.
- 선택창의 썸네일은 열었을 때 현재 페이지의 최대 6개만 작은 크기로 순서대로 읽는다. 이전·다음으로 과거 묶음에도 접근하며 선택창이 본문 높이와 옵션 폭을 바꾸지 않는다. 페이지 전환·닫기·종료에서는 읽기를 취소하고 썸네일을 해제하며 늦은 읽기 결과를 적용하지 않는다.
- 기존 장면을 수정할 때는 `.blend` 파일과 바꿀 내용을 선택한다. 참고 이미지를 추가할 수 있고, 이전 모델링 결과를 다음 작업의 장면으로 사용해 수정할 수 있다.
- 최대 삼각형 수는 `0`(자동) 또는 `1`~`1,000,000`으로 지정한다. 요청에 고정한 값을 내보낼 모델에 적용한다. 자동에서는 삼각형 수를 맞추기 위해 형상을 줄이지 않는다.

## 작업과 결과

Eidolon은 기본적으로 Blender를 창 없이 실행한다. Blender 창 표시 옵션을 켜면 해당 요청의 Blender 창만 열린다. 두 모드는 같은 파일 명령, 렌더, 삼각형 제한, 저장과 취소 방식을 사용한다. 창 없이 실행할 때도 EEVEE 렌더에 필요한 GPU 환경을 사용한다. AI는 참고 이미지와 현재 장면의 객체 정보, 기존 장면을 수정하는 경우 그 장면의 렌더를 보고 모델링 작업을 한 번 작성한다. 내장 키트는 허용된 모델링 함수 호출과 리터럴 값을 읽어 적용한다. 기본 도형·사용자 정의 메시·곡선·재질·배치 등으로 모델을 만들거나 지정한 부품을 수정한다. AI가 생성한 일반 Python 파일을 그대로 실행하지 않는다.

모델링 계획은 여러 방향의 원본을 공통 기준 높이와 중심선에 맞춰 비교하고 정면의 폭·높이, 좌우의 깊이·전후 위치·돌출, 후면의 윤곽·부품 배치, 제공된 윗면의 폭·깊이를 하나의 3D 치수와 연결부로 정리한다. 입력이 한 장이거나 시점이 충돌하거나 가려진 부분은 확인할 수 있는 범위에서 보수적으로 추정한다. 윤곽과 부품 접합을 먼저 맞추고 표면 마감은 마지막에 한다. 이 지침은 이미지 치수를 자동으로 측정하지 않는다.

Blender가 작업을 적용해 렌더와 파일을 저장하고 검증을 마치면 그 결과를 바로 반환한다. 결과 렌더를 AI에 다시 보내는 자동 보정이나 최종 비교는 없다. 결과 화면에서 GLB를 3D로 확인하고 저장된 결과 위치를 열 수 있으며, 바꿀 부분이 있으면 **이 모델 이어서 수정**으로 새 작업을 요청한다. 새 요청의 `.blend`, `.glb`와 렌더는 기존 `Modeling/<요청 ID>/Draft`에 저장하고 작업 로그는 요청 폴더에 남긴다. 선택한 원본 모델과 과거 결과는 그대로 보존한다.

결과에는 내보낸 GLB의 실제 삼각형 수를 기록한다. 상한을 초과한 경우에만 출력용 작업 장면의 지오메트리를 필요한 만큼 줄이며, 상한 이하이면 수를 맞추기 위해 형상을 바꾸지 않는다. 렌더와 `.blend`, `.glb`는 같은 결과 형상을 담는다. 최종 GLB가 상한을 충족하지 못하면 실패로 처리한다.

현재 연결은 앱이 Blender와 Codex를 실행하는 방식이다. Blender MCP 애드온이나 MCP 연결은 필요하지 않다. 모델링 요청은 앱의 공용 작업 큐에 접수하며 취소·종료는 해당 요청이 시작한 프로세스에 적용한다.

## 모델링 MCP

App의 `eidolon_model_3d`는 화면 입력을 바꾸지 않고 같은 `ModelingInput`, 공용 FIFO와 `ModelAsync` 실행 경로에 요청을 추가한다. 이미지 생성 방식과 별개로 저장된 네이티브 GPT(Codex CLI) 실행 파일·모델과 설치된 Blender를 사용한다. 요청 시 설정·참조 경로·수정 원본·설명·삼각형 상한을 사본으로 고정하고, 설치·로그인·초기화·종료·유지 관리 조건을 확인한 뒤에만 접수한다. Claude나 WSL 실행으로 전환하지 않으며 Blender 창 표시는 기본 꺼짐이다.

`reference_path` 한 장 또는 `views`의 `front`·`left`·`right`·`back`·선택 `top`을 받는다. 둘을 동시에 받지 않는다. 기존 `.blend`를 수정하는 `source_blend_path`에는 설명이 필수이며, 새 모델은 이미지가 있으면 설명을 비울 수 있다. 입력은 절대 로컬 경로의 기존 PNG·JPEG·WebP와 `.blend`다. Windows의 UNC·디바이스 접두사는 파일 존재 확인·읽기·디코딩 전에 거절한다. 이미지는 기존 App 로더의 32MB·4천만 픽셀 제한과 디코딩 검사를 거친다. 파일 내용은 실행을 시작할 때 기존 엔진이 요청 폴더에 복사하므로 시작 전 원본을 옮기거나 변경하지 않는다. 투명도·방향 라벨은 그대로 전달한다.

접수 응답의 `request_id`는 기존 `Modeling/<GUID>` 경로의 GUID이며 완료를 뜻하지 않는다. MCP 요청의 공용 대기 제목은 `3D [<GUID>]`다. `eidolon_get_modeling_result`는 GUID만 받아 관리 경로의 `Control/Draft.json`과 비어 있지 않은 `Draft/Model.blend`·`Draft/Model.glb`를 확인한 뒤 완료 경로와 키트가 기록한 실제 내보내기 삼각형 수를 반환한다. 링크를 경유하는 결과 경로와 임의 조회 경로는 받지 않는다. 기존 자동 보정 시기의 `Refined`가 있는 작업은 최종 선택을 추측하지 않고 `unknown`으로 반환한다.

대기·실행은 기존 큐와 현재 모델링 입력에서, 최근 취소·실패는 화면의 기존 실행 상태에서 확인한다. 과거 실패는 기존 `Failure.txt` 존재만 확인하고 내용을 읽어 노출하지 않는다. 별도 결과 저장소나 취소 이력 파일은 만들지 않는다. 시작 전 대기 비우기, 더 오래된 취소, 앱 재시작 등으로 증거가 남지 않은 요청은 `unknown` 또는 `not_found`이며 취소·실패·완료로 단정하지 않는다. 공용 상태·정확한 현재 요청 제목·취소·대기 비우기는 [MCP 문서](Mcp.md#3d-모델링-도구)의 기존 도구를 사용한다.

실행 파일·작업 폴더·출력 경로·스크립트·임의 Python을 도구 인자로 지정할 수 없다. 결과 파일 읽기 외 전송 확장은 추가하지 않았으며, 실제 모델링·MCP 호출·앱 실행·빌드·테스트 검증은 수행하지 않았다.

## 소유 경계

`Eidolon.Modeling`은 기존 Eidolon 솔루션 안의 별도 프로젝트이며 `Eidolon.Core`, Avalonia, Eidolon 앱을 참조하지 않는다. Blender 설치, 모델링 실행, 키트와 입력·결과 계약은 모델링 프로젝트가 소유한다. Eidolon 앱이 프로젝트 참조를 통해 기능을 조립하고 기존 다운로드·프로세스 실행과 큐를 연결한다. 엔진·모델링 화면의 번역과 상태 표시는 App이 소유한다.
