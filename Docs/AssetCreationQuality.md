# 다면도 제작 품질 검증

2026-10-21 사용자가 지정한 최근 다면도 기준 이미지로 5방향 생성과 생성 결과의 묶음 표시를 확인했다. 생성 완료·파일 계약·UI 동작과 시점·외형의 품질을 구분한다. 이 기록은 사용한 기준 이미지와 Codex 경로의 비교이며 다른 이미지·모델의 품질을 보증하지 않는다.

## 입력과 실행 경로

- 최근 실제 다면도 작업 `cc20ca2e2a2e45d8a1a5584261231a5a`의 기준 이미지를 그대로 사용했다. 파란색·금색 갑옷, 빨간 망토, 오른손을 든 자세와 왼팔 방패가 있는 캐릭터다. 계약 검증용 fixture는 기준에서 제외했다.
- 기존 Codex 생성 조건을 복사하고 앱의 `StudioWorkQueue → AssetCreationService → StudioService → CodexImageEngine` 경로에서 총 20장의 PNG를 생성·비교했다. 별도 이미지 생성 API나 ComfyUI 경로로 전환하지 않았다.
- 작업 데이터·설정·출력은 Git에서 제외된 `artifacts/quality-tests/20261021` 아래에 보관했다. 실제 사용자 설정·출력 폴더를 바꾸지 않았다.
- 새 묶음 전체 생성과 방향별 선택 재생성을 구분해 확인했다. 최종 시트는 마지막으로 선택된 방향별 결과이며, 최초 자동 생성만으로 같은 품질이 나온다는 뜻은 아니다.

## 시점 보정과 관찰

초기 결과에서 좌우가 같은 방향을 보거나 후면의 머리가 앞을 향하고 윗면이 높은 사선 시점에 머무는 문제를 확인했다. 방향별 카메라 지시, 화면상 방향과 가까운 면·가려지는 면을 구체화했다. 우측은 대상 자신의 오른쪽에서 바라보며 앞쪽이 화면 오른쪽, 좌측은 화면 왼쪽을 향하도록 구분했다.

윗면은 수직 아래를 보는 짧은 전용 지침으로 구성했다. 전신 정면·높은 사선 구도·가슴 앞면·길게 보이는 몸통과 다리를 제외하도록 해당 생성 요청의 설정 사본에만 지침을 추가했다. 묶음에 저장한 설정과 사용자의 공통 제외 지침은 유지했다.

| 방향 | 최종 결과에서 확인한 내용 | 남은 한계 |
|---|---|---|
| 정면 | 앞면 얼굴 가리개·가슴 문양·장비와 손짓이 보임 | 세부 장식·대칭과 정확한 정면 투영은 보장하지 않음 |
| 우측 | 앞쪽이 화면 오른쪽인 측면이며 반대쪽 방패가 작게 보임 | 두께·장식의 원본 일치는 보장하지 않음 |
| 좌측 | 앞쪽이 화면 왼쪽인 측면이며 가까운 방패가 보임 | 손가락·갑옷 세부 형태에 편차가 남음 |
| 후면 | 머리 뒤·등·망토가 보이고 앞면 얼굴이 나오지 않음 | 망토의 펼침과 굴곡이 다른 방향과 정확히 일치하지 않음 |
| 윗면 | 머리 정수리·어깨 중심의 형태이며 얼굴·가슴 문양·긴 다리가 가려짐 | 실제 3D 형상에서 계산한 수직 투영은 아님 |

방향 구분과 윗면의 가림 관계는 개선되었다. 단일 기준 이미지로 보이지 않는 면의 정답을 확인할 수 없으며, 정밀한 3D 모델링용 정투영이나 모든 방향의 형태 일치를 통과했다고 판정하지 않는다. 이번 작업에서 ComfyUI의 이미지 품질은 검증하지 않았다.

## 저장·내보내기 검증

최종 묶음은 `3541a939cec24bf59ee999b367c52484`다. `FiveViews`와 `front → right → left → back → top` 순서를 확인했다. 내보낸 시트는 5120×1024, 항목별 1024×1024이며 `Loop=false`, `FramesPerSecond=0`이다. 원본·프레임·생성 조건·시트 manifest를 기존 내보내기 경로로 작성했다.

스프라이트 애니메이션 제작 UI·새 요청·MCP 도구는 제거하고 과거 기록과 이미지 파일은 보존했다. 과거 4방향 자료는 항목 수 4와 기존 라벨을 유지하는 것을 확인했다.

## 생성 결과 묶음과 필터 검증

기존 `JobStore`의 읽기 경로에서 다음을 확인했다. 기존 ID를 생성 조건 JSON에 연결하며 별도 저장소나 인덱스를 만들지 않았다.

| 확인 대상 | 실제 결과 |
|---|---|
| 기본 PNG 단위 조회 | 20장, 기존 MCP 조회 기본값 유지 |
| 전체 필터 | 일반 이미지 7개 + 다면도 묶음 2개 = 9개 |
| 일반 이미지 필터 | 7개, 묶음 제외 |
| 다면도 필터 | 2개, 일반 이미지 제외 |
| Job 폴더 없는 PNG·JSON 사본 조회 | 같은 다면도 묶음 2개 |
| 페이지 크기 1 | 방향별 이미지가 페이지 사이에 분리되지 않음 |
| 과거 4방향 자료 | 기존 4개 항목 유지 |

소속을 확인할 수 없는 과거 이미지는 임의로 묶지 않았다. 새 생성·재생성의 이력은 같은 묶음에 연결하고 화면은 각 방향의 최신 결과를 표시한다.

실제 `ResultsView`를 1280×900과 최소 창 1024×740에서 실행·캡처했다. 렌더링된 방향 버튼의 명령으로 윗면을 선택해 실제 미리보기 대상이 변경됨을 확인했다. 일반 이미지 필터, 빠른 필터 전환 후 최신 결과 적용, 묶음 선택 시 선택 삭제 비활성도 확인했다. 저장·재사용·편집·학습은 선택한 개별 이미지를 대상으로 유지하며 묶음 전체 파일 삭제는 추가하지 않았다.

앱과 캡처 프로그램 빌드는 경고·오류 0개로 완료했다. 이 빌드 결과는 이미지의 기하학적 정확성을 뜻하지 않는다.

캡처 후 최신 일반 앱을 다시 실행하고 실제 창이 열린 것을 확인했다. 실행 중인 앱의 MCP 조회에서 `initialized=true`, `idle=true`, 대기 요청 0개와 빈 오류를 확인했으며, `eidolon_create_views` 제공과 `eidolon_create_sprite_animation` 제거를 확인했다.

이 검증 뒤 제작 화면의 남은 프레임·동작 문구를 이미지·시점 기준으로 정리하고 Excel 원본에서 JSON·C#을 다시 생성했다. 영어 사용법 안내도 변환 결과가 잘리지 않도록 줄였다. 이 마지막 문구 수정 후에는 추가 빌드·실행·캡처를 수행하지 않았다. 이번 커밋·푸시 작업에서는 실행 파일 생성과 GitHub 릴리스 게시를 수행하지 않는다.
