# Eidolon 릴리스 정책

## 배포 파일

Windows x64는 자체 포함 단일 EXE로 배포한다. macOS ARM64와 Intel은 자체 포함 단일 실행 파일을 넣은 `Eidolon.app`을 ZIP으로 배포한다. 대상 플랫폼의 실행·업데이트 방법은 [앱 업데이트](ApplicationUpdate.md)를 따른다.

- 실행에 필요한 .NET 런타임, 라이브러리, 고정 데이터와 기본 설정을 포함한다. 사용자가 DLL이나 JSON을 따로 복사하거나 개발 폴더에서 실행할 필요가 없어야 한다. 필수 리소스는 기존 번들과 임베디드 로더를 사용한다.
- 플랫폼별 [게시 프로필](../Eidolon.App/Properties/PublishProfiles)은 `PublishSingleFile`, `SelfContained`, `IncludeNativeLibrariesForSelfExtract`를 켜고 전체 콘텐츠 추출과 트리밍을 기본으로 사용하지 않는다. 디버그 정보는 `DebugType=embedded`로 포함하며 PDB를 배포 파일에 따로 추가하지 않는다.
- 사용자 설정, 작업 데이터와 로그는 기존 저장 경로에 둔다. 앱 실행 파일이나 번들 안에 기록하지 않는다. 라이선스·저작권 고지는 기존 내장 리소스와 [외부 소프트웨어 고지](ThirdPartyNotices.md)로 제공한다.
- 릴리스 설정을 맞추기 위해 일반 개발 실행이나 기존 사용자 환경을 바꾸지 않는다.

## 게시

- 실행 파일 생성과 게시는 사용자가 해당 릴리스에 대해 요청했을 때만 수행한다. 필요한 배포 빌드와 별도 테스트·앱 실행 검증은 구분하고 [검수, 커밋과 게시](WorkingRules.md#검수-커밋과-게시)의 범위를 지킨다.
- [배포 워크플로](../.github/workflows/release.yml)로 동일한 소스 커밋의 플랫폼별 파일을 만든다. 앱 버전·태그·소스 커밋·파일 이름·SHA-256을 게시할 파일에 맞춘다.
- 총괄이 릴리스 문서와 다운로드 링크를 관리한다. [버전별 릴리스 노트](Releases/)와 GitHub 게시문에 한국어·영어로 버전, 플랫폼·아키텍처별 실제 다운로드 링크, 실행 방법과 확인 범위를 적는다. 게시할 버전에 맞춰 [한국어 README](../README.md)와 [영어 README](../README.en.md)의 안내를 갱신한다.
- 이미 게시한 버전의 배포 파일을 덮어쓰지 않는다. 배포 형식이나 내용 변경은 새 버전으로 게시한다.
