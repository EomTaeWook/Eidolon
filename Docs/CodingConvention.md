# Eidolon 코딩 컨벤션

사용자 지시와 적용 경로의 [AGENTS.md](../AGENTS.md)를 우선한다. 작업 범위·계층·검증은 [작업 규칙](WorkingRules.md), 현재 구현의 책임 경계는 [아키텍처](EidolonArchitecture.md)를 따른다.

## C# 형식

- 직접 작성하는 파일은 UTF-8 BOM 없음, CRLF를 사용한다. C# 프로젝트 전체에서 nullable 참조 형식을 비활성화하며, 파일별 `#nullable enable`, nullable 참조 형식, null-forgiving 연산자로 예외를 만들지 않는다.
- 변수명은 풀네임으로 작성한다. 메서드 선언과 호출의 인자를 자동 줄바꿈하지 않는다.
- 블록 네임스페이스와 명시적 생성자를 사용한다. `sealed`, 주 생성자와 위치 기반 레코드를 사용하지 않는다. 속성·메서드·제어문은 여러 줄 블록으로 작성하고 식 본문 멤버와 한 줄 블록을 사용하지 않는다.
- 제어문의 중괄호를 생략하지 않는다. 삼항 연산자, `checked`, `unchecked`와 익명 객체를 사용하지 않는다.
- 비모델 최상위 타입은 파일별로 나눈다. 내부 클래스를 만들지 않고 모델과 DTO는 소유 계층의 `Models` 아래에서 기능별로 묶는다.

## 조건과 반환값

- 한 `if`에는 한 조건만 작성한다. `&&`나 `||`로 합치지 말고 조건별 `if`, 중첩 또는 앞선 반환으로 순서를 드러낸다. Boolean과 null 비교는 `== true`, `== false`, `== null`, `!= null`처럼 명시한다.
- 선택적 도메인 상태는 의미가 분명한 `None`·`Unknown` 또는 상태 객체로 표현한다. 정상 입력에서 발생할 수 있는 실패는 경계에서 확인하고, 불가능한 내부 상태는 임의의 기본값으로 숨기지 않는다.
- 사용하지 않는 호출 결과를 변수에 저장하지 않는다. 반환값이 계약에 필요하지 않은 메서드는 `void`로 작성한다.
- 예외 메시지에는 실패한 대상과 이유를 담고 비밀값과 개인 정보는 넣지 않는다.

## 의존성과 데이터 소유권

- .NET 기본 기능을 우선하며 새 외부 라이브러리는 Dignus로 제한한다. 기존 의존성과 주입 경계를 재사용한다. 서비스·저장소·시간과 난수 공급자는 생성자로 주입하며 전역 정적 서비스나 저장소를 두지 않는다. 정적 멤버는 상수, 진입점과 부작용 없는 연산에 사용한다.
- 데이터마다 원본 저장 책임을 하나로 정한다. 이미 있는 저장·조회 경계를 주입받거나 필요한 값만 변환하고, 실행 경로가 다르다는 이유로 같은 파일·스키마·저장 DTO나 캐시를 만들지 않는다.
- 새 저장소가 필요하면 기존 소유자와 호출·등록·소비 경로를 먼저 확인한다. 중복되지 않는 책임, 저장 수명, 보호 경계, 이전·복구 방법을 구현 전에 문서에 남긴다. 설정과 인증 정보처럼 수명과 보호 수준이 다른 값은 편의를 위해 섞지 않는다.
- 같은 행위를 다른 모듈에서도 처리한다는 이유로 미리 공통화하지 않는다. 불필요한 매니저·팩토리·래퍼와 나중에 쓰려는 필드를 추가하지 않는다.
- 시간 필드에는 단위를 드러내고 저장·전송·실행 단위는 경계에서 변환한다. 재현 가능한 생성은 기존 시드와 난수 공급자 계약을 따른다.

## 생성 파일과 Markdown

- 다국어 데이터는 [문자열 데이터 변환](StringData.md)의 Excel 원본과 공식 변환 순서를 사용한다. 생성 JSON·C#을 직접 수정하지 않는다.
- 문서는 현재 계약을 설명한다. 같은 규칙은 책임 문서 한곳에 두고 다른 문서에서는 링크로 연결한다. 제목, 상대 경로, 코드 블록은 실제 구조에 맞춘다.
- 미구현·미결 사항은 확정 계약과 구분한다. 임시 수치는 `[PROVISIONAL]`, 미결 정책은 `[TBD]`로 표시하며 실행하지 않은 검증은 결과로 기록하지 않는다.
- 검증 여부와 완료 보고는 [검수, 커밋과 게시](WorkingRules.md#검수-커밋과-게시)를 따른다. 작업에 필요한 파일 읽기와 생성물 변환을 별도의 검증으로 확대하지 않는다.
