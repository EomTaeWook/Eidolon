# 이미지 편집

편집 탭은 그림체 변경과 부분 고치기를 제공한다. 원본 이미지와 변경 설명을 입력하고 기존 생성 방식·체크포인트·LoRA·공용 FIFO를 사용한다. 입력과 마스크는 접수 시 바이트 사본으로 고정하며 원본 파일을 덮어쓰지 않는다.

## 원본 특징 유지

일반 참고 생성과 이미지 편집은 참고 이미지를 고르면 앱에 설정한 Codex 실행 파일·이미지 입력 가능한 실행 모델로 유지할 특징을 한 번 자동 추출한다. 기존 Codex 로그인과 모델 설정을 사용하며 별도 로컬 모델을 설치하지 않는다. `CodexImageEngine.DescribeReferenceFeaturesAsync`가 텍스트 응답만 요청하고 `image_generation`을 비활성화한다. 고정 프롬프트는 App의 `ReferenceFeatures.txt`, 주입은 기존 `CodexInstructionTemplates`와 App DI가 소유한다. 로컬 `PromptConverter`는 이 분석에 사용하지 않고 번역·형식 정리 전용을 유지한다.

추출 대상은 보이는 얼굴·실루엣·비율·주요 색·의상·장비의 수와 위치 등 식별 특징이다. 당시 입력한 변경 요청에서 명시적으로 바꾸려는 특징은 제외하도록 요청한다. 가려진 면·확인할 수 없는 특징·불명확한 해부학적 좌우를 추측하지 않으며 배경·시점·포즈·그림체는 별도 유지 요청이 없으면 고정하지 않는다. 추출 결과는 영어 구문으로 표시하고 사용자가 기존 참고 이미지 영역에서 확인·수정하거나 **특징 다시 읽기**를 실행한다. 변경할 특징은 보존 목록에서 제거해야 하며 특히 ComfyUI에서는 서로 모순되는 특징을 완벽히 자동 해결한다고 보장하지 않는다.

일반 생성과 편집은 각각의 `GenerationReferenceDraft`가 특징과 읽기 상태를 소유한다. 요청할 때 설정·이미지 바이트·현재 원문을 고정하고 기존 FIFO에서 실행한다. 이미지 변경·제거, 특징 직접 수정, 재분석, 요청 설정 변경과 앱 종료 뒤 늦은 결과·오류는 현재 입력을 덮지 않는다. 분석 중 원문을 바꾸면 이전 분석을 무효화하며 입력할 때마다 재요청하지 않는다. 사용자는 다시 읽기 또는 직접 수정으로 결과를 확정한다. 대기 작업 비우기와 취소도 기존 폐기 콜백·요청 토큰·프로세스 종료 경계를 사용한다. 분석 대기·실행 중에는 결과를 확인하기 전 해당 생성·편집을 접수하지 않는다.

Codex를 사용할 수 없거나 추출이 실패해도 선택한 참고 이미지와 마스크를 유지한다. 같은 영역에 오류와 직접 입력 안내를 표시하며, 로컬 태그 변환 모델로 분석을 대체하지 않는다. 입력한 특징은 `GenerationReferenceInput.PreservationPrompt`의 요청 사본으로 기존 `StudioService.GenerateAsync`에 전달한다. 실제 생성 프롬프트에 특징을 합성하고 기존 Job·PNG 옆 JSON의 `PositivePrompt`에 기록하며 `UserPrompt`·기본 지침·저장 설정은 원문을 유지한다. 별도 특징 파일·캐시·영속 설정·결과 DTO는 추가하지 않는다. 결과 재사용에서는 원본을 다시 읽고 특징을 새로 추출·확인하며 수동 편집한 특징을 독립 필드로 복원하는 계약은 추가하지 않는다.

부분 고치기의 원본·마스크·선택 밖 합성은 기존 흐름을 유지한다. MCP 일반·참고 생성과 그림체 편집은 [호출자 모델과 유지 특징 왕복](Mcp.md#호출자-모델과-유지-특징-왕복)의 수동 특징·공식 sampling 계약을 사용한다. 같은 App 처리 메서드에 `2025` 초기화·세션의 POST SSE와 `2026-07-28` 요청별 MRTR을 연결하며 서버의 로컬 Codex를 추가 실행하지 않는다. 다면도 요청의 특징 기본 빈 값과 기존 제작 계약은 유지한다. 이번 기능은 소스 연결만 진행하며 빌드·테스트·앱/모델 실행·추출 품질·실제 생성으로 확인하지 않았다. 특징 자동 추출과 원본 형태의 정확한 재현은 구분한다.

## 화면

기본 모드는 기존 그림체 변경이다. 편집 캔버스는 현재 선택한 편집 원본과 파일명을 표시한다. 마지막 생성 결과를 편집 원본 대신 표시하지 않으며, 원본이 없으면 중앙에 이미지 추가 안내와 버튼을 제공한다. **부분 고치기**를 켜면 같은 원본 이미지 위에서 브러시로 고칠 부분을 칠한다. 선택 영역은 현재 테마의 강조색으로 표시하고 브러시 크기·지우개·선택 지우기를 제공한다. 이미지의 화면 여백은 선택 대상에 포함하지 않는다. 사진의 EXIF 회전·반전과 창 크기에 맞춘 표시 배율을 선택 좌표에 반영한다.

선택하지 않은 상태에서는 부분 편집 실행을 비활성화한다. **영역 선택**으로 같은 원본의 마스크 편집을 연다. 별도 결과 미리보기 영역과 미리보기 전환 버튼은 두지 않고, 편집에 필요한 원본 캔버스만 유지한다. 마스크 편집 중에만 브러시 입력과 선택 강조를 활성화한다. 실행 요청을 추가하면 입력 이미지와 선택은 다음 편집을 위해 유지하며, 다시 칠하려면 영역 선택을 누른다. 완성 이미지는 상단의 **생성 결과** 버튼으로 확인한다. 참고 이미지를 바꾸거나 제거하면 기존 마스크를 비운다.

## 요청과 저장

기존 `GenerationReferenceMode`의 0~2를 보존하고 `Inpaint=3`을 추가한다. `GenerationReferenceInput.MaskData`는 선택 알파가 있는 PNG다. 알파 0은 보존, 알파 255는 수정이며 중간값은 선택 경계다. 마스크 표시용 작업 해상도는 최대 1024이며 원본 좌표에 맞춰 정규화한다.

`StudioService`가 이미지 크기·바이트 제한, 마스크 크기·비율과 실제 선택 유무를 확인하고 기존 Job의 `Inputs/Reference.png`와 `Inputs/Mask.png`에 EXIF 방향을 반영한 사본을 저장한다. `JobRecord`와 이미지 옆 기존 `GenerationMetadata`에 `ReferenceMaskPath`를 추가한다. 과거 결과는 마스크 경로가 비어 있는 기존 모드로 계속 읽는다. 새 저장소·큐·전역 마스크 파일은 만들지 않는다.

결과 재사용은 부분 편집 모드·원문·원본과 마스크를 함께 복원한다. 파일이 없으면 다시 원본을 선택하거나 영역을 칠할 때까지 실행하지 않는다. 마스크를 읽는 동안 참고 이미지가 바뀌거나 앱이 종료되면 늦은 결과를 적용하지 않는다.

## 생성과 합성

ComfyUI는 원본과 마스크를 각각 업로드하고 기본 `ImageScale`·`LoadImage`·`InvertMask`·`VAEEncodeForInpaint`를 사용한다. 마스크의 알파를 선택값으로 변환하고 기존 모델·LoRA·프롬프트·sampler를 사용한다. `grow_mask_by=6`은 해당 노드의 기본값이며 별도 인페인팅 모델이나 커스텀 노드를 설치하지 않는다. 그림체 변경의 Canny·ControlNet은 기존 모드에만 적용한다. [ComfyUI 기본 노드](https://github.com/Comfy-Org/ComfyUI/blob/v0.38.0/nodes.py), [마스크 노드](https://github.com/Comfy-Org/ComfyUI/blob/v0.38.0/comfy_extras/nodes_mask.py).

Codex는 기존 읽기 전용 실행에 원본과 검정·흰색 마스크 안내 이미지를 반복 `--image`로 전달한다. 흰색은 수정, 검정은 보존이며 마스크 자체를 결과에 그리지 않도록 App의 `Inpaint.txt` 템플릿에서 지시한다. 이는 마스크 안내 이미지를 함께 제공하는 경로이며 전용 마스크 API 호출은 추가하지 않는다. [OpenAI 공식 CLI 문서](https://learn.chatgpt.com/docs/developer-commands?surface=cli).

두 방식 모두 생성 원본을 Job에 보존하고 게시 전에 선택한 부분만 원본 이미지에 합성한다. 마스크 알파 0인 영역은 정규화한 원본에서 가져오고, 경계는 선택 알파로 혼합한다. 게시 결과는 원본 크기를 유지하고 선택 밖의 알파를 보존한다. 배경 투명화가 켜져 있으면 생성 영역에 처리한 뒤 합성하므로 선택 밖의 원본 배경을 다시 쓰지 않는다. 최종 PNG·JSON 게시와 중간 파일 정리는 기존 JobStore 경로를 사용한다.

UI의 부분 편집을 추가하며 MCP의 `eidolon_edit_image`는 기존 그림체 편집 계약을 유지한다. 새 MCP 도구·마스크 입력 인자는 추가하지 않는다. ComfyUI 편집 UI는 설치된 로컬 프롬프트 변환기로 사용자 설명을 정리한 뒤 확인·수정한 변환문을 생성에 사용한다. Codex 편집은 원문을 바로 전달한다. 마스크와 고정 편집 지침은 변환하지 않으며 상세 입력 계약은 [프롬프트 변환](PromptConversion.md)을 따른다.

이번 기능은 빌드·테스트·앱 실행·캡처·실제 부분 생성으로 검증하지 않았다. 선택 안쪽의 생성 품질과 경계의 자연스러움은 실제 결과로 확인해야 한다.
