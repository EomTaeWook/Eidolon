# Eidolon 작업 규칙

이 문서는 Eidolon의 개발·변경 규칙을 소유한다. 구조와 실행 흐름은 [아키텍처](EidolonArchitecture.md), 공통 C#·Markdown 표현은 [CodingConvention](ReusableArchitecture/CodingConvention.md), 다국어 생성 절차는 [StringData](StringData.md), 배포 형식은 [ReleasePolicy](ReusableArchitecture/ReleasePolicy.md)를 따른다.

## 적용 순서와 작업 범위

- 사용자 지시와 요청 범위를 먼저 적용한다. 현재 경로에 적용되는 `AGENTS.md`와 이 문서, 변경 대상의 구조 문서를 읽고 작업한다.
- Bough의 Core/App 경계, DI·템플릿 로딩, Excel 다국어와 UI 구성을 참고한다. Bough의 프로젝트별 기능이나 재사용 문서의 Unity·Actor·Tick·RepoDB 구조를 자동으로 가져오지 않는다.
- 요청과 무관한 작업 트리 변경을 복원하거나 정리하지 않는다. 기존 사용자 데이터, 설치 환경과 실행 중인 앱을 임의로 변경하지 않는다.
- 미사용 추상화, 임시 캐시와 같은 개념의 두 번째 저장소를 미리 만들지 않는다. 기존 책임을 찾고 호출·주입 경계를 재사용한다.

## 제품과 화면

- 기본 생성 경험의 핵심 입력은 자연어 프롬프트이며 생성 탭에서 참고 이미지를 선택적으로 추가한다. 이미지 편집 탭은 기존 이미지의 그림체 변경을 담당한다. 기본 모델 계열은 SDXL이며 세부 파라미터는 내부 프리셋이 소유한다.
- 생성 탭은 설명만으로 생성하거나 참고 이미지를 바탕으로 새로 생성한다. 참고 이미지는 생성·편집 모두 설명 입력 아래에 같은 제목·전체 너비 추가 버튼·아이콘·여백으로 제공하고 선택했을 때 이미지·변경·제거·강도를 표시한다. 편집에서만 필수 이미지 안내를 표시한다. 제거하면 설명만으로 생성한다. 이미지 편집 탭은 기존 이미지와 편집 설명을 요구하고 그림체 변경을 낮은 강도로 시작한다. 정확한 형태 고정을 보장하는 기능으로 표현하지 않는다. 생성·편집의 설명·참고 이미지·강도는 각각 유지하고 서로의 요청에 섞지 않는다. 참고 이미지는 선택 시 읽어 요청에 고정하고 원본 파일은 변경하지 않는다. 갤러리의 이 이미지로 편집은 편집 탭을 연다. 결과 재사용은 참고 생성이면 생성 탭, 그림체 변경이면 편집 탭으로 연결하며 참고 파일이 없으면 다시 선택할 때까지 해당 요청을 막는다.
- 기본 생성 지침·제외할 요소는 설정에서 관리하고 생성 화면은 저장된 내용을 읽기 전용으로 보여준다. 요청별 지침 편집은 향후 MCP 작업 범위로 두며 현재 생성 UI에 편집·기본값 불러오기를 제공하지 않는다. ComfyUI 노드 그래프를 제품 화면에 노출하지 않는다.
- 생성 프롬프트는 자동으로 추가하는 LoRA 호출 단어, 사용자가 입력한 이미지 설명, 설정의 생성 지침 순서로 합성한다. 이미지 설명 뒤에 설정 지침을 붙이며 입력·지침에 이미 포함한 호출 단어는 중복 추가하지 않는다. 제외할 요소는 별도 입력으로 전달한다. 합성 순서를 바꾸어도 이전 결과의 저장된 생성 조건은 보존한다.
- 이미지 생성과 LoRA 학습·이어 학습, 학습 결과의 생성 연결을 한 프로그램에서 제공한다.
- 배경 투명화는 ComfyUI 생성 뒤 앱의 기존 배경 제거 서비스에서 수행한다. 모델에 맞는 입력 크기·정규화와 출력 마스크를 사용하고 대상을 구분하지 못한 마스크를 성공한 투명 이미지로 저장하지 않는다. 원본은 기존 Job 저장 경계에 보존하고 처리 오류는 코드·번역 문장으로 알린다.
- 학습 화면은 이미지 입력과 단계 수·모델·트리거 설정을 중심으로 배치하며 학습 기록 목록은 표시하지 않는다. 학습하기·학습 폴더 만들기는 스크롤과 분리한 같은 실행 영역에서 항상 접근할 수 있게 한다. 상태·진행률·남은 시간은 하단에 표시하고 작업 파일·로그는 기존 저장 경계에 보존한다. 선택한 LoRA의 트리거는 생성에 자동 적용하며 사용자가 같은 트리거를 다시 입력하게 하지 않는다.
- 학습 입력은 흰색 배경·검정색 배경 목록으로 나누고 각각 이미지 추가·폴더 추가·개별 제거·목록 비우기를 제공한다. 폴더 추가는 해당 목록에 하위 폴더의 지원 이미지를 가져오며 같은 목록의 중복 파일은 제외한다. 목록은 축소 이미지·파일명을 표시하고 빈 영역과 최대 높이를 제한해 불필요한 여백·중첩 테두리를 줄인다. 설정의 저장 폴더 입력은 공용 경로·폴더 버튼 스타일을 사용한다. 폴더 열기는 위치 조회만 수행하고 선택이나 학습 범위를 변경하지 않는다.
- 사용자는 흰색 배경으로 학습할 이미지와 검정색 배경으로 학습할 이미지를 각 목록에 선별한다. 같은 파일을 두 목록에 추가할 수 있고 두 목록은 한 요청·한 데이터셋으로 학습해 LoRA 하나를 만든다. 목록 소속의 배경 값과 선택 파일·입력·설정을 큐 추가 시 사본으로 고정한다. 파일 내용은 실행 시 복사하며 투명·반투명 영역만 해당 배경색에 합성한다. 이미 있는 배경·해상도와 원본 이미지·캡션은 보존한다. 새 학습과 이어 학습에 같은 준비 경계를 사용한다.
- 학습 폴더 만들기는 선택한 이미지와 같은 이름의 설명 .txt를 사용자가 지정한 위치의 새 하위 폴더에 저장한다. 기존 설명이 있으면 우선 사용하고 없으면 공통 설명·트리거로 작성한다. 이미지 내용을 자동 해석한 설명으로 표현하지 않는다. 실제 학습과 폴더 생성은 `LoraTrainer.PrepareDatasetAsync`를 함께 사용하며 폴더 생성만으로 학습을 실행하지 않는다. 생성 결과의 학습 연결은 흰색 목록에 한 장을 추가하고 이미 입력한 학습 목록·설정을 유지한다.
- 설치는 엔진 탭에 두고 사용자가 설치 경로를 선택하게 한다. 기존 Python·Git·ComfyUI 설치를 필수 전제로 삼지 않는다.
- 엔진 설치 하위 탭은 실행 환경 설치·복구와 서버 연결·모듈 조회를 담당한다. 모델 설치·삭제 목록은 모델·LoRA 하위 탭에만 배치해 두 화면에 중복 표시하지 않는다.
- 엔진과 생성 모델의 준비 상태는 상단의 간결한 상태 줄로 구분한다. 모델이 없을 때만 별도 준비 안내와 다음 동작을 강조하며 준비 완료 상태를 큰 배너로 반복하지 않는다. 모델 설치·관리 이동은 작업 중에도 사용한다. 엔진 설치 뒤 모델이 없으면 모델·LoRA 탭으로 이어지며 생성 화면에서도 모델 준비 안내와 이동 버튼을 제공한다. 선택 모델이 없으면 생성 요청을 비활성화하고 설치·가져오기 또는 외부 서버 모델 준비를 안내한다. 모델 목록 조회·스크롤은 설치 중에도 유지하고 변경 동작만 기존 유지 관리 조건으로 제한한다.
- 파일 가져오기는 모델 목록 상단에 둔다. 항목이 선택되었을 때만 해당 모델 정보를 표시하고 자동 판별 계열의 수정은 상세 설정에 둔다. LoRA 호출 단어는 LoRA 선택 시에만 제공한다. 가져오기에는 이전 선택 항목의 계열·트리거 입력을 적용하지 않는다.
- 상단 탭은 제품 브랜드와 같은 줄의 간결한 중립 배경에 배치한다. 생성 화면은 하나의 입력 패널과 이미지 중심 미리보기로 구성하고 반복 안내와 중첩 카드를 줄인다. 현재 이미지의 입력 프롬프트·적용 지침·제외 요소는 미리보기 아래 생성 정보에서 펼쳐 읽고 복사한다. 생성 기록과 결과 정보는 생성 결과 탭에 둔다. 별도 작업 로그 펼침 영역을 만들지 않고 로그 폴더 열기는 설정에서 제공한다. 공통 하단은 현재 상태·진행률·대기열을 담당한다.
- 하단 상태·진행 영역에는 버튼을 절대로 배치하지 않는다. 취소, 요청 추가와 대기열 비우기 등 작업 동작은 해당 생성·학습 화면의 실행 영역에 둔다. 하단에는 상태, 진행률, 남은 시간, 대기 건수와 오류 정보만 표시하며 클릭으로 실행되는 펼침 컨트롤도 두지 않는다.
- 모델·LoRA 파일 관리는 엔진 탭 안에 두며 생성 화면은 사용할 자산을 선택한다. 설정은 기본 생성 지침·제외할 요소를 소유하고 저장 뒤 생성 화면의 읽기 전용 표시도 갱신한다. 결과 재사용은 현재 설정의 지침을 유지하고 사용자 입력·모델·LoRA·배경 옵션·시드를 복원한다. 이미지 폴더 열기는 생성 결과 갤러리의 상단에 둔다.
- 생성 화면 상단에서 설치한 모델과 체크포인트 폴더의 별도 다운로드 모델을 같은 목록으로 선택한다. 생성 화면 진입과 수동 새로고침은 기존 자산 스캔·서버 조회 경계를 사용하고 현재 선택과 호환 LoRA를 유지한다. 파일 가져오기·설치·삭제는 엔진 탭에 둔다.
- 생성의 모델과 LoRA 선택은 입력 패널 상단에 연속 배치한다. 모델 선택 뒤 호환 LoRA를 바로 고를 수 있어야 하며 프롬프트·생성 지침·실행 버튼으로 두 선택 영역을 분리하지 않는다. LoRA는 스크롤 목록의 행을 눌러 적용·해제하고 여러 항목을 함께 적용한다. 목록이 5개 이상이거나 검색어가 있을 때 이름·파일명·호출 단어 검색을 제공한다. 기존 `AssetItem.IsSelected`가 선택을 소유하고 검색은 선택을 바꾸지 않는다. 적용 수는 선택했을 때만 표시하고 전체 적용 이름과 앞에 붙는 호출 단어는 도움말로 제공한다.
- 생성 입력은 모델·LoRA 선택, 프롬프트·선택적 참고 이미지, 시드·배경 옵션 순서로 한 패널에 배치한다. 이미지 편집은 같은 모델·LoRA·시드·배경·실행 패널을 사용하고 생성과 동일하게 설명 입력 다음에 참고 이미지·강도를 배치한다. 두 작업의 구분은 상단 탭이 소유하고 중복 모드 선택 목록은 두지 않는다. 설정의 생성 지침은 읽기 전용 펼침 영역에서 읽고 복사한다. 펼침 헤더는 영역 전체 너비를 사용하고 제목과 우측 화살표 사이에 여백을 확보하며 열린 상태에서는 화살표를 위로 향하게 한다. 요청·대기열 동작은 스크롤 밖의 같은 패널 하단에 고정한다. 엔진 준비와 유지 관리 중에도 다음 입력을 작성하고 요청 추가는 기존 `CanQueue` 조건으로 제한한다. 같은 작업에서 함께 바꾸는 항목은 한 영역에 모으고 주요 동작을 찾기 위해 위아래로 이동하게 만들지 않는다.
- 생성 시드는 기본 자동 생성과 직접 지정을 지원한다. 큐 추가 시 실제 값을 고정해 요청 영역에 표시하고 미리보기와 결과 정보는 해당 이미지의 저장된 시드를 표시한다. 직접 지정한 시드는 정수·범위 검증을 통과해야 생성할 수 있다. 결과 재사용은 저장된 시드도 복원하며 이후 입력 변경이 대기 요청의 시드에 영향을 주지 않게 한다.
- 생성 결과는 현재 출력 폴더의 실제 PNG를 기준으로 카드 갤러리를 제공한다. 한 페이지에 12장씩 비동기로 조회하고 해당 페이지의 같은 이름의 프롬프트 JSON과 축소 이미지만 로드한다. PNG가 없으면 표시하지 않으며 JSON이 없거나 손상되어도 이미지 조회는 유지한다. 페이지 변경·종료 시 이미지 메모리를 해제하고 늦게 끝난 요청은 반영하지 않는다. 상단에 이미지 수·폴더 열기·새로고침·전체 삭제, 하단에 페이지 이동을 둔다.
- 결과 화면은 왼쪽 카드 갤러리를 주영역으로 두고 오른쪽 이미지·프롬프트 패널의 초기 너비와 이미지 높이를 제한한다. 좌우 사이의 보이는 손잡이를 드래그해 패널 너비를 조절하고 갤러리의 열 수는 조절한 너비에 맞춘다. 클릭과 키보드 초점 이동으로 오른쪽 내용을 바로 갱신하며 갤러리의 페이지·스크롤을 유지한다. 갤러리는 클릭으로 한 장, Ctrl+클릭으로 개별 추가·해제, Shift+클릭으로 범위를 선택하고 다중 선택 삭제를 제공한다. 체크 표시 없이 얇은 강조 테두리로 선택을 표시한다. 선택 수와 선택 해제·선택 삭제는 갤러리 상단에 두며 선택은 현재 페이지에 적용한다. 오른쪽은 마지막으로 클릭하거나 키보드로 이동한 이미지를 표시하고 선택 삭제는 선택한 이미지들에 적용한다. 카드 높이는 이미지와 설명에 맞추고 남은 화면 높이까지 늘리지 않으며 이미지 전체를 표시한다. 열 수는 왼쪽 갤러리의 실제 너비로 정한다. 오른쪽 이미지 위에 모델·시드·해상도, 아래에 저장·프롬프트 재사용·이미지 편집·학습 연결을 동일한 높이와 아이콘 간격의 2열 버튼으로 고정하고 그 아래 스크롤 영역의 첫 내용으로 입력 프롬프트·적용 지침·제외할 요소를 표시한다. 재사용은 JSON의 입력·사용 가능한 모델과 LoRA·배경 옵션·시드를 복원하고 누락된 자산을 알리며 생성 지침·제외할 요소는 현재 설정을 사용한다.
- 언어와 라이트·블랙 테마는 설정에서 즉시 적용·저장한다. 라이트 테마는 아키텍처의 Bough 색상을 따른다.
- 사용법은 생성·이미지 편집·학습을 별도로 안내하고 각 항목에 해당 탭으로 바로 이동하는 버튼을 둔다. 생성의 선택적 참고 이미지와 편집의 필수 이미지·그림체 변경·강도 차이를 설명한다.
- 아이콘은 버튼의 전경색을 따라 테마와 상태에서 읽을 수 있게 한다. 특정 탭의 안내 문구를 다른 탭의 공통 상태로 사용하지 않는다.
- 작업과 충돌하지 않는 결과 저장·프롬프트 재사용·폴더 열기는 실행 중에도 사용할 수 있게 한다. 설정 편집을 전체 비활성화하지 않고 저장 가능 시점은 버튼과 안내로 표시한다. 학습 요청은 필요한 입력이 채워졌을 때 활성화하고 실행 버튼 옆에서 부족한 입력을 안내한다.

## 타입과 파일 구성

- 모델을 제외한 최상위 클래스·인터페이스·enum은 타입별 파일로 분리한다. 파일명은 타입명과 맞춘다.
- 서비스, 저장소, 실행기, 명령과 Presenter를 한 파일에 모으지 않는다. `AtomicJsonFile`, `SettingsStore`, `JobStore`, `ISeedProvider`, `CryptoSeedProvider`는 각각 자기 파일을 사용한다.
- 함께 사용하는 DTO·설정·데이터 모델은 응집된 모델 파일에 둘 수 있다. 이 예외로 서비스·저장 구현을 모델 파일에 섞지 않는다.
- 중첩 클래스는 사용하지 않는다. 한 타입에서만 쓰는 비공개 구현도 별도 파일의 `internal` 타입으로 분리한다. 외부 라이브러리·생성 코드는 원본 소유 경계를 따른다.
- 같은 Avalonia partial 타입의 `.axaml`·`.axaml.cs` 분리는 유지한다.
- 생성 코드는 수작업 파일 분리·수정 대상이 아니다. Excel·스키마·변환기를 고친 뒤 재생성한다.
- 프로젝트에 외부 번역 JSON·고지문을 포함할 때 리소스 포함·복사 계약은 유지하고 `Visible=false`로 솔루션 탐색기의 링크 항목을 숨긴다.

## Core와 App 경계

- Core는 생성·학습·설치·저장·큐와 실행 계약을 담당한다. App, Avalonia, DataContainer, 언어·테마·번역 서비스에 의존하지 않는다.
- Core에 `IStringProvider`, `StringHelper`, Excel 키 번호나 UI 리소스 키를 넣지 않는다. 실행 데이터와 사용자 표시 문장의 책임을 분리한다.
- Core 오류는 `StudioException`의 `StudioMessageCode`·인자, 진행 알림은 `WorkProgress`의 코드·인자·진행률로 전달한다.
- 메시지 코드와 Excel 키의 대응 및 표시 문장 생성은 App이 소유한다. 오류를 저장할 때는 코드·인자를 보존하고 표시할 때 번역한다.
- 전체 사용자 설정 저장과 언어·테마는 App이 소유한다. Core에는 실행에 필요한 `StudioSettings` 사본을 전달한다.
- App이 Dignus DI 컨테이너와 HTTP 클라이언트, 큐·서비스의 조립과 수명을 소유한다. View에서 별도 컨테이너·HTTP 클라이언트·큐를 만들지 않는다.
- ViewModel은 입력·바인딩·화면 상태와 결과를 연결한다. Presenter는 큐 진입, UI 스레드 복귀, 비동기 실행·진행·취소와 예약 수명을 담당한다.
- 시간·난수와 실행 의존성은 기존 주입 경계를 사용한다. 전역 정적 서비스로 런타임 상태를 소유하지 않는다.

## 다국어와 생성물

- 문자열 원본은 `Excel/String.xlsx` 하나다. 새 문구와 번역은 Excel에 추가하고 ExcelToJson → JsonToCSharp 순서로 생성한다.
- `Datas/String.json`과 `DataContainer/Generated`를 직접 편집하지 않는다. 별도 번역 데이터 사전이나 문자열 원본을 만들지 않는다.
- 기존 문자열 ID·이름과 사용자 데이터를 보존한다. 한국어·영어의 포맷 인자와 사용 계약을 함께 맞춘다.
- `TemplateDataLoader`가 생성 로더를 호출하는 Bough 방식으로 시작 전에 데이터를 준비한다. 릴리스에서 개발 폴더의 JSON에 의존하지 않는다.
- 사용자 프롬프트·캡션·모델 이름과 외부 도구 원문을 임의로 번역하지 않는다.

## 큐와 프로세스 수명

- 생성·학습 요청은 공용 FIFO 큐에 넣고 하나씩 실행한다. UI에서 직접 별도 병렬 생성·학습 경로를 만들지 않는다.
- 대기 요청은 Dignus `SynchronizedArrayQueue`를 사용한다. 컬렉션 동기화에 직접 작성한 `lock`을 중복하지 않으며 요청 추가·현재 실행·종료 상태는 기존 작업 큐가 소유한다.
- 추가 시 입력·설정·자산을 복사해 이후 화면 편집이 대기 요청을 바꾸지 않게 한다. 실제 학습 파일 복사 시점은 학습 시작이다.
- 학습 중에만 학습 화면의 실행 영역에 학습 취소를 제공한다. 큐의 현재 요청 취소를 기존 토큰 경계에 전달해 학습 프로세스와 자식을 정리하며 생성 작업에는 취소 버튼을 표시하지 않는다. 완성 LoRA 등록 중에는 취소를 허용하지 않는다. 대기 작업 비우기는 아직 시작하지 않은 요청에만 적용하며 앱 종료 시 실행·대기 작업을 정리한다. 대기열을 임의로 영속화하거나 다음 실행에 자동 재개하지 않는다.
- 설치·모델 변경·접속 변경은 기존 유지 관리 경로를 사용한다. 서버 주소 변경은 마지막 값을 예약하고 대기 작업이 끝난 뒤 적용한다.
- 접속 설정은 서버 주소 하나를 사용한다. 별도 포트·외부 모드 설정을 다시 만들지 않는다. 실행 중인 서버를 먼저 확인하고 조건에 맞는 로컬 주소에서만 설치 엔진을 실행한다.
- 앱 소유 프로세스와 기존 서버의 연결을 구분한다. 정지·종료는 앱이 시작한 프로세스에만 적용하며 기존 서버는 연결만 끊는다.
- 앱 소유 ComfyUI의 자식 프로세스 수명은 `ProcessRunner`와 `WindowsProcessLifetime`을 통한다. 프로세스 이름·포트만으로 다른 프로세스를 종료하지 않는다.
- 기존 서버의 다른 요청에 영향을 주는 전역 interrupt나 전체 큐 삭제를 사용하지 않는다. 개별 작업 ID를 사용한다.
- 학습은 앱 소유 로컬 환경에서 실행하고 생성 서버를 멈춘 뒤 종료·실패·취소 시 복구한다. 학습 환경 확인·실행 Python은 기존 Windows 프로세스 수명 경계에 자식과 함께 등록하고 취소 시 출력 읽기도 중단한다. 프로세스 종료 대기 전에 소유 수명 핸들을 닫아 자식의 출력 핸들 때문에 취소 완료가 막히지 않게 한다. 앱 종료 중에는 서버를 다시 시작하지 않는다.
- 이어 학습 결과는 새 LoRA로 저장하고 기반 LoRA를 보존한다. 가중치 이어 학습을 optimizer·스케줄까지 복원한 전체 재개로 표현하지 않는다.
- 학습 단계 수는 직접 입력하거나 기존 `TrainingPreset`의 빠른·기본 프리셋으로 채운다. 허용 범위는 프리셋이 소유하며 UI·Core 양쪽 입력 경계에서 적용한다. 큐에는 실제 단계 수를 고정하고 작업 기록·실행 인자·진행률도 이 값을 사용한다. 남은 시간은 학습 출력에 추정치가 있을 때 `WorkProgress`의 시간 값으로 전달하며 App이 표시한다. 준비 단계에서 시간을 임의로 만들어 표시하지 않는다.

## 저장, 모델과 로그

- 설정은 App의 `SettingsStore`, 자산은 `AssetLibrary`, 작업은 `JobStore`, 설치 상태는 `RuntimeInstaller`가 각각 소유한다. 화면 목록·캐시를 별도 권위 저장소로 만들지 않는다.
- JSON 저장은 `AtomicJsonFile`의 임시 파일·교체·백업 경로를 사용한다. 손상·미지원 스키마를 기본값으로 덮어쓰지 않는다.
- 설정 변경에는 기존 데이터 이전을 같은 저장 경계에 둔다. 알 수 없는 기존 필드를 보존하고 재실행 때 같은 이전을 반복하지 않는다.
- 사용자 이미지·캡션과 기반 LoRA 원본을 보존한다. 자산 등록 해제를 가중치 파일 삭제로 확대하지 않는다. 모델 설치 목록의 삭제 버튼은 사용자 확인 후 해당 로컬 체크포인트 파일과 부분 다운로드를 실제 삭제하고 자산 등록을 제거한다. 삭제는 기존 유지 관리 큐에서 작업이 없는 상태에 처리하며 설치 경로·자산 ID·배포 파일명을 확인한다.
- 생성 이미지 폴더 변경은 새 요청과 갤러리 조회에 적용하고 기존 결과를 임의로 이동하지 않는다. 이미지와 같은 이름의 프롬프트 JSON이 출력 결과의 생성 조건을 소유하며 Job 폴더 없이 함께 옮겨도 조회·재사용할 수 있다. 출력 파일의 게시·조회·삭제·이전은 기존 `JobStore`가 소유하고 별도 결과 저장소·인덱스를 만들지 않는다.
- App의 기본 생성 이미지 폴더는 해당 사용자의 `%LOCALAPPDATA%/Eidolon/Images`다. `SettingsStore`가 기존 빈 경로를 이 기본값으로 읽고 저장하며 명시한 경로는 보존한다. 폴더 입력에는 폴더 선택과 폴더 열기를 구분한다. 설정의 폴더 열기는 입력된 경로를 사용하고 학습의 폴더 열기는 학습 범위를 바꾸지 않는다.
- 생성 이미지 폴더에는 최종 PNG와 같은 이름의 프롬프트 JSON을 함께 저장한다. 파일명은 생성 시각과 GUID로 정하고 JSON에 입력·합성 전 지침·적용 지침·제외 요소·모델·LoRA·배경 옵션·시드·해상도·파라미터·생성 시각을 보존한다. 원본과 처리 임시 파일은 Job 폴더에 보관하며 최종 결과만 출력 위치에 게시한다. PNG가 게시된 뒤 실행 기록 저장에 실패해도 완성 결과를 삭제하지 않는다. 결과에서 학습으로 연결할 때는 이미지 한 장을 고정해 공유 폴더의 다른 결과가 섞이지 않게 한다.
- 이미지 삭제는 확인한 PNG와 같은 이름의 프롬프트 JSON을 실제 삭제한다. 선택 삭제는 현재 페이지의 선택한 이미지들, 전체 삭제는 현재 출력 폴더 모든 페이지에 적용한다. 삭제 확인에 이미지 수·파일 대상·복구 불가를 표시하며 기존 유지 관리 큐에서 실행·대기 작업이 없을 때 처리한다. 출력 루트·직속 부모 경로·확장자·재분석 지점을 확인하고 Job 폴더·원본·학습 이력·로그는 보존한다. 이전 생성 결과는 원본·기존 JSON을 보존하면서 한 번만 이전하며 완료 표식으로 삭제한 결과를 다시 만들지 않는다.
- 모델 목록은 실제 준비된 자산을 기준으로 하고 계열 판별·선택과 모델·LoRA 호환성을 기존 자산 경계에서 처리한다.
- 버전·설치 경로는 `RuntimeLayout`, 생성·학습값은 기존 프리셋과 실행기가 소유한다. 같은 값을 여러 화면·문서에 독립 설정으로 복제하지 않는다.
- Dignus.Log로 파일 로그를 기록한다. stdout/stderr 파일 타깃은 기존 `ProcessLogFile` 경계를 사용하고 상세 로그를 하단 상태 문구에 그대로 노출하지 않는다.
- 설치 모듈 조회는 기존 `RuntimeInstaller`의 설치 소유 기록을 재사용한다. Core는 파일·버전·상태 정보만 반환하고 App이 표시 문구를 번역한다. 모듈 조회 때문에 별도 저장소나 프로세스 실행 경로를 만들지 않는다.

## C# 형식과 문서

- 직접 작성하는 파일은 UTF-8 BOM 없음, CRLF를 사용한다. nullable은 프로젝트 전체에서 비활성화한다.
- 명시적 생성자와 블록 네임스페이스·본문, 제어문의 중괄호와 명시적인 Boolean·null 비교를 사용한다. 나머지 C# 표현 규칙은 [CodingConvention](ReusableArchitecture/CodingConvention.md)을 따른다.
- 문서는 최종 구현의 책임·타입·경로를 설명한다. 제거된 인터페이스와 화면을 현재 계약으로 남기지 않는다. 마이그레이션에 필요한 이전 필드만 해당 절차에서 설명한다.
- 구조는 아키텍처, 작업 규칙은 이 문서, 다국어 명령은 StringData가 각각 소유한다. 다른 문서는 링크로 연결하고 같은 규칙을 별도 원본으로 복제하지 않는다.
- 미구현·미결 정책과 실제 실행 여부를 구분한다. 실행하지 않은 내용을 성공 결과로 기록하지 않는다.

## 검수, 커밋과 게시

- 현재 사용자의 검증 중단 지시를 유지한다. 별도 요청 전에는 빌드, 테스트, 앱 실행·캡처, 하네스, 정적 검사, diff check와 데이터 대조를 실행하지 않는다.
- 전체 검수 요청은 요청된 정적 코드 검수 범위에 적용한다. 이를 빌드·테스트·실행 검증 허가로 확대하지 않는다.
- 필요한 소스 읽기·편집과 Excel 변환기의 산출물 생성은 계속 수행한다. 이 작업을 별도 검증 절차로 확대하지 않는다.
- 테스트 프로젝트·테스트 코드는 별도 요청 없이 추가하지 않는다. 완료 보고에는 검증 미실시를 명시한다.
- 커밋·푸시와 실행 파일 게시·업로드는 사용자 요청 범위에 따라 수행한다. 커밋·푸시를 요청받으면 필요한 Git 상태·원격 확인과 해당 작업을 진행하되 앱 검증을 재개하지 않는다.
- 커밋에는 요청 범위의 원본·생성물·문서를 포함하고 빌드 출력, 사용자 설정·데이터, 설치 엔진과 모델 가중치를 넣지 않는다. 기존 원격 이력을 임의로 덮어쓰지 않는다.
