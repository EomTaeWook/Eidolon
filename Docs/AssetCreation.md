# 연관 이미지 에셋 제작

에셋 제작 탭은 기준 이미지 한 장에서 스프라이트 프레임 또는 모델링 참고용 삼면도 초안을 만든다. 현재는 기존 img2img 참고 생성과 항목별 설명을 사용한다. 대상의 외형 유지, 자연스러운 반복 동작, 시점 간 형태·치수의 정합성을 보장하는 기능은 아니다. 실제 3D 모델을 출력하지 않는다.

## 사용자 흐름

왼쪽에서 기준 이미지를 선택하고 제작 종류와 대상 설명을 입력한다. 생성 결과의 큰 미리보기에서 우클릭 메뉴의 에셋 제작을 선택하면 해당 이미지와 기존 설명을 가져와 제작 탭을 연다. 오른쪽에서 제작 묶음을 선택해 결과를 비교하고 내보낸다. 실행 버튼과 취소·대기열 동작은 입력 패널 하단에 두고 공통 상태 영역에는 상태·진행만 표시한다.

| 종류 | 추가 입력 | 결과 |
|---|---|---|
| 스프라이트 애니메이션 | 동작 설명, 프레임 수, FPS, 선택적 프레임별 포즈 설명 | 순서가 있는 프레임, 반복 재생 |
| 캐릭터 삼면도 | 대상 설명 | 정면·측면·후면 |
| 물체 삼면도 | 대상 설명 | 정면·측면·윗면 |

프레임별 포즈 설명은 프레임 수만큼 한 줄씩 입력한다. 비워 두면 공통 동작의 단계별 설명으로 초안을 만든다. 모델·LoRA·참고 강도·배경 투명화·픽셀 아트·출력 크기·열 수는 접힌 상세 설정에 둔다. 모델과 LoRA 선택은 기존 자산 선택을 공유하고 공통 지침은 저장한 설정을 사용한다. 입력·편집 탭의 참고 이미지와 설명은 바꾸지 않는다.

현재 기본값은 스프라이트 8프레임, 10 FPS, 참고 변경 강도 0.45, 출력 프레임 256×256, 시트 4열이다. 프레임 수는 2~32, FPS는 1~60, 프레임 한 변은 16~2048 px, 열 수는 1~32다. 삼면도는 항상 3항목이며 기본 출력 크기는 1024×1024다. UI에서 직접 바꾼 출력 크기는 상세 설정에서 확인한다. 참고 입력은 기존 32 MiB·4천만 픽셀 제한을 따른다. 출력 크기는 내보내기 크기이며 모델의 생성 해상도를 변경하지 않는다.

결과 목록에서 항목을 선택하면 생성 설명을 읽고 수정한 설명으로 선택 항목만 다시 만들 수 있다. 재생 중에는 선택 항목의 설명 편집·재생성·교체를 막는다. 스프라이트 순서를 앞뒤로 바꿀 수 있으며 재생은 이미지가 있는 항목을 순환한다. 탭을 벗어나면 재생을 멈춘다. 픽셀 아트 미리보기와 내보내기는 nearest 보간을 사용한다. 미리보기는 생성 원본을 보여주고 공통 캔버스 정렬은 내보내기에서 적용한다.

이미지 교체는 선택한 이미지의 사본을 작업 폴더에 PNG로 저장한다. EXIF 방향을 적용하고 사용자 원본을 보존한다. 기존 결과나 실패 전 이미지를 덮어쓰지 않는다. 누락되거나 읽을 수 없는 결과는 다시 만들거나 교체할 수 있다.

## 실행과 기록

기존 `StudioWorkPresenter → StudioWorkQueue → StudioService.GenerateAsync` 경계를 재사용한다. 제작 묶음 하나가 FIFO 요청 하나이며 프레임은 순서대로 생성한다. 별도 생성 큐·GPU 사용권을 만들지 않는다. 모델·LoRA·설정·기준 이미지·시드를 요청 시 사본으로 고정하고 묶음에 저장한 조건으로 이어 만들기와 선택 재생성을 실행한다.

`AssetCreationService`가 묶음 준비·항목 생성·재생성·교체를 소유한다. 저장은 기존 `JobStore`가 `Jobs/<묶음 ID>/AssetCollection.json`으로 처리한다. 기준 파일은 같은 작업 폴더의 `Reference.bin`에 보존한다. 생성 항목은 기존 Job 및 PNG·생성 조건 JSON과 연결하며 `SourceJobId`, 이미지 경로와 실제 결과 시드를 기록한다. 별도 결과 저장소나 인덱스를 만들지 않는다.

일부 실패 시 그 항목에서 멈추고 완성한 이미지를 보존한다. 제작 취소는 기존 현재 요청 토큰을 전달하며 완료한 이미지와 기록을 유지한다. **미완성 이어 만들기**는 완료한 항목을 건너뛰며 누락된 이미지도 다시 생성한다. 손상된 이미지가 남아 있으면 선택 재생성·교체를 사용한다. 이어 만들기·선택 재생성·교체·순서 변경은 큐가 비었을 때 수행한다. 요청을 비우거나 앱을 종료하면 대기 중인 묶음을 취소 상태로 기록한다. 비정상 종료한 준비·실행 중 묶음은 다음 시작에서 중단 상태로 바꾸고 자동 재개하지 않는다.

선택 재생성은 새 시드를 사용할 수 있다. 실패하면 이전 이미지·원본 Job·실제 이미지 시드를 유지하면서 실패 코드·인자를 기록한다. 모든 항목에 이미지가 있으면 실패 전 이미지를 포함해 내보낼 수 있으며 검토는 사용자가 수행한다.

## 내보내기 계약

출력 위치 아래 새 `Eidolon-Assets-<ID 일부>-<새 GUID>` 폴더를 만든다. 기존 파일을 덮어쓰지 않는다.

| 파일 | 내용 |
|---|---|
| `Frames/001.png` 등 | 공통 크기로 정렬한 개별 PNG |
| `Sources/001.png` 등 | 선택한 결과의 원본 사본 |
| `Sources/001.json` 등 | 원본 옆 생성 조건 JSON이 있을 때 그 사본 |
| `Sheet.png` | 검토한 항목 순서로 합성한 투명 PNG 시트 |
| `Sheet.json` | 묶음 종류, 프레임 크기, 순서·라벨, 시트 좌표, 기준점, FPS와 원본 Job·시드 |

배경 제거를 선택한 요청은 기존 앱 배경 제거 서비스를 사용한다. 기존 배경을 가진 이미지와 교체 이미지의 배경을 내보내기에서 임의로 제거하지 않는다.

알파가 16보다 큰 영역을 대상 경계로 잡고 입력 캔버스의 긴 변을 기준으로 각 경계를 정규화한 뒤 전체 항목의 가장 큰 경계에 맞춘 공통 비율로 크기를 조절한다. 교체 이미지의 해상도가 달라도 같은 캔버스 단위로 처리한다. 각 대상은 프레임 하단 중앙에 정렬한다. 투명 빈 이미지는 거부한다. 이 정렬은 발·손 등 해부학적 기준점을 추적하거나 흔들림을 보정하는 기능이 아니다.

`Sheet.json` 형식은 `Eidolon.AssetSheet`, 스키마 버전은 1이다. `X/Y/Width/Height`는 시트 좌상단 원점의 픽셀 사각형이다. `PivotX/PivotY`는 각 셀 안의 정규화된 좌표 0.5/1.0이다. `FramesPerSecond`와 `Loop`는 스프라이트 재생 정보이며 삼면도는 `Loop=false`다. 열은 왼쪽에서 오른쪽, 행은 위에서 아래로 채운다. 최대 시트 면적은 6천4백만 픽셀이며 초과하면 출력 크기를 줄여야 한다.

실패·취소한 내보내기 폴더에는 작성한 사본 일부가 남을 수 있다. 완료 메타데이터는 PNG 저장 이후 작성한다. 원본·묶음 기록은 유지하고 재시도는 새 출력 폴더를 만든다.

## 책임 경계

| 위치 | 책임 |
|---|---|
| Core `Domain/Models/AssetCreation` | 요청·묶음·항목·시트 DTO |
| Core `Application/AssetCreation` | 기존 생성 유스케이스를 호출하는 묶음 작업·진행 |
| Core `Infrastructure/AssetCreation` | 이미지 사본 가져오기·시트 합성 |
| 기존 `JobStore` | 묶음 기록·조회·중단 처리·메타데이터 저장 |
| App `ViewModels/AssetCreation` | 입력·큐 연결, 결과 선택·재생·비트맵 수명 |
| App `Services/AssetCreation` | 크기를 제한한 이미지 읽기·미리보기 디코딩 |
| App `Mcp/McpService.cs` | 같은 기능의 도구 정의·private 처리 메서드 |

도구와 연결 계약은 [MCP 연결](Mcp.md)이 소유한다. 전송 라이브러리에는 이미지·에셋 업무 종속성을 추가하지 않는다.
