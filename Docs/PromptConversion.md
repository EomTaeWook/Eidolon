# 로컬 프롬프트 변환

## 구현 범위

엔진 탭에서 프롬프트 변환 모델을 설치하고, 일반·참고 이미지 생성과 그림체·부분 편집의 한글·영어 입력을 대상 이미지 모델의 형식에 맞춰 정리한다. UI는 입력 → 필요하면 변환하기 → 같은 입력란에서 확인·수정 → 생성 순서로 진행하며 MCP의 자동 변환과 구분한다. 입력은 태그·구문·문장 또는 혼합형일 수 있다. 출력 형식은 입력 모양이 아닌 요청에 고정된 생성 방식·체크포인트의 안내로 결정하며 번역과 형식 정리는 한 번의 로컬 모델 요청으로 처리한다.

대상 모델은 `Qwen3-4B-Instruct-2507`의 `Q4_K_M` GGUF 배포본이다. 실행기는 공식 llama.cpp Windows x64 CPU 배포본을 사용한다. 앱에 새로운 NuGet 추론 라이브러리를 추가하지 않는다. 다운로드 출처와 고지는 [외부 소프트웨어 고지](ThirdPartyNotices.md)를 따른다.

현재 설치 정의는 llama.cpp `b11889`와 모델 배포 revision `ae44f08e1392f39c0e474af10c3ff8355c8b6688`을 고정한다. 모델 파일은 `Qwen_Qwen3-4B-Instruct-2507-Q4_K_M.gguf`, 2,497,280,736바이트이며 다운로드 URL·SHA-256·실행 경로는 기존 `RuntimeLayout`이 소유한다. 설치 정의의 확인과 실제 파일 다운로드·실행 성공은 구분한다.

## 입력과 생성

로컬 변환 모델이 설치된 ComfyUI 생성·편집 화면에는 프롬프트 아래 왼쪽에 작은 변환 버튼을 제공한다. 변환은 기존 공용 FIFO에서 수행하고 성공한 결과로 해당 입력란을 교체한다. 별도 변환문 입력란이나 원문 사본을 두지 않으며 사용자는 같은 입력란에서 계속 수정한다. 변환 중 입력·대상 모델·관련 실행 설정이 바뀌면 늦은 결과와 오류를 현재 입력에 반영하지 않는다. 취소·실패 시 입력을 교체하지 않는다. 일반 생성과 편집의 입력·변환 진행 상태는 서로 독립적으로 유지한다. 변환은 선택 동작이며 현재 입력이 비어 있거나 해당 입력의 변환이 진행 중이면 생성하지 않는다. 별도 사용 설정은 두지 않는다.

UI 생성 요청은 현재 입력란의 문자열을 요청 사본에 고정하고 이미지 생성 때 다시 변환하지 않는다. MCP는 대화형 확인 단계를 추가하지 않으며 기존 요청 접수 시 설정·원문·체크포인트·LoRA·참고 이미지의 사본을 고정한다. 변환과 생성은 같은 공용 FIFO와 요청 취소·종료 경계를 사용한다.

저장된 생성 방식이 Codex이면 UI·MCP 모두 로컬 변환기를 거치지 않고 원문을 기존 Codex 이미지 생성·편집으로 바로 전달한다. 이 화면에는 로컬 변환문 확인 단계를 표시하지 않는다. Codex가 설치되어 있다는 이유로 저장된 ComfyUI 생성 방식을 자동 변경하지 않는다.

ComfyUI 변환에는 해당 요청의 체크포인트 안내를 전달한다. 태그 중심 모델은 태그로, 자연어 설명을 안내하는 모델은 영어 설명·문장으로 정리하도록 지시한다. 미확인 모델의 특수 어휘는 추측하지 않는다. 수량·좌우·부정 조건·구도·고유명사와 호출 단어를 보존하고, 안내의 예시를 요청 내용으로 오해하거나 요청하지 않은 품질·작가·스타일 태그를 추가하지 않도록 지시한다. 이미 적절한 입력은 불필요하게 다시 쓰지 않도록 한다.

`UserPrompt`는 생성 요청에 고정한 입력과 재사용 문자열을 보존하고 `PositivePrompt`에는 실제 합성한 문자열을 기록한다. UI에서 변환했다면 교체·수정한 현재 입력이 `UserPrompt`가 되며, MCP 자동 변환은 접수한 원문을 `UserPrompt`에 유지하고 실제 변환문을 합성한다. 기존 LoRA 호출 단어 → 사용자 설명 → 저장 생성 지침의 합성 순서를 유지한다. 저장된 공통 지침과 제외 지침은 변환 모델이 다시 작성하지 않는다. 별도 변환 이력 저장소나 태그 목록을 만들지 않는다.

MCP의 ComfyUI 일반·참고 생성과 그림체 편집은 기존 GenerationViewModel.EnqueueGeneration에서 설치 상태를 고정하고 같은 FIFO 실행 중 한 번 변환한다. MCP의 model_id가 명시되면 그 체크포인트를 사용하며 생략하면 접수 시 UI 선택 모델을 고정한다. 이후 UI 선택이 바뀌어도 대기 요청의 안내를 바꾸지 않는다. UI 부분 고치기의 사용자 설명도 같은 수동 변환·확인 경로를 사용하며 마스크·선택 영역 지침은 변환하지 않는다. 다면도·학습은 로컬 자동 변환을 추가하지 않으며 고정 시점·학습 캡션 지침을 유지한다. MCP의 요청별 생성·제외 지침과 미설치 시 작성 계약은 [MCP 연결](Mcp.md)을 따른다.

## 설치와 실행 경계

기존 `RuntimeLayout`·`RuntimeInstaller`·`FileDownloader`·`RuntimeManifest`를 통해 설치 경로·다운로드·해시 확인·설치 상태를 관리한다. 프롬프트 변환기의 설치 상태 때문에 ComfyUI 전체가 설치된 것으로 처리하지 않는다.

이미 저장된 엔진 설치 경로가 있으면 변환기도 그 경로를 사용하며 변환기 설치만으로 기존 엔진·자산의 경로를 바꾸지 않는다. 저장된 경로가 없을 때만 입력한 경로를 최초 설치 대상으로 사용한다. 카드에는 실제 설치 대상 경로를 표시한다.

같은 카드의 변환 모델 삭제는 확인창에서 대상 폴더와 복구 불가를 안내하고 기존 유지 관리 큐에서 실행·대기 작업이 없을 때만 처리한다. `RuntimeInstaller`가 설치 소유 기록·버전과 링크 경로를 확인한 뒤 변환 모델·전용 실행기 폴더 및 해당 실행기의 설치용 압축·부분 다운로드를 삭제한다. 설치 실패·중단으로 남은 파일도 같은 설치 기록을 기준으로 정리한다. 설치 기록의 변환기 항목만 비우고 ComfyUI 상태·생성 모델·LoRA·작업 결과·로그·저장 경로는 유지한다. 삭제 후에는 일반·참고 생성과 편집도 원래 입력을 사용하며 같은 경로에 다시 설치할 수 있다. 이번 삭제 기능은 아직 빌드·실행·실제 파일 삭제로 검증하지 않았다.

변환은 요청당 CPU 프로세스로 수행하고 기존 `ProcessRunner`·`WindowsProcessLifetime`와 요청 취소 토큰을 사용한다. 별도 상주 서버·큐·GPU 사용권·설정 저장소를 만들지 않는다. 설치된 모델의 파일이 누락되거나 변환이 실패하면 이미지 생성으로 넘어가지 않으며 원문을 성공 결과로 자동 반환하지 않는다.

## 검증 범위

이번 UI 변환문 확인·수정과 모델별 변환 연결은 빌드·테스트·실행·변환 품질 검증을 수행하지 않았다. 아래 내용은 이전 버전의 확인 기록이다.

2026-10-26에 실제 다운로드·설치, 한글 3건·영문 1건의 변환과 미리 취소된 요청을 확인했다. 예제에는 수량·좌우·제외 조건·사용자 트리거를 포함했고 이 PC의 CPU 변환은 약 8~10초였다. 일반·참고 생성의 자동 적용과 원문·적용 프롬프트 분리를 실제 UI·ComfyUI 연결로 확인했다. MCP 생성은 별도 변환 없이 전달한 영어 입력을 유지했고, 한국어·라이트 및 영어·블랙 화면을 캡처했다. 전체 확인 범위는 [0.1.0-beta.5 릴리스 노트](Releases/0.1.0-beta.5.md)를 따른다. 예제 통과가 다른 입력의 의미 보존이나 이미지 품질을 보장하지 않는다.
